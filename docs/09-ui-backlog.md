# 09 — UI/UX бэклог (по сравнению с Discord, 2026-09-26)

Референс — Discord desktop (структура, плотность, привычные паттерны), визуальный язык — macOS (docs/08). Каждая задача — с критерием готовности; закрывается visual-тестом.

## P0 — хром окна и каркас

1. **Верхняя полоса окна (title bar)** — 38 px на всю ширину, `-webkit-app-region: drag`; на macOS `titleBarStyle: 'hiddenInset'` + `trafficLightPosition {x:12,y:12}`, слева зарезервировано 80 px под светофор — **ничего под ним не рисуется**. В полосе: ← → навигация (история комнат), по центру — имя workspace (или «Calaba»), справа — поиск (см. 3), «Входящие/упоминания», «?». На Windows/Linux — свои кнопки окна справа (`titleBarOverlay`) или стандартная рамка. Веб — та же полоса без drag.
2. **Рейл workspace** (72 px): иконки 48 px со скруглением 16 → при hover/active 12 (как Discord), слева «пилюля»-индикатор (8 px — непрочитанное, 40 px — активный), бейдж непрочитанных/упоминаний красным с числом, зелёный значок динамика на иконке workspace, где я в voice; tooltip с именем справа; разделитель; «+» и «Обзор». Иконка workspace — картинка или 2 буквы.
3. **Глобальный поиск** (`Cmd/Ctrl+K` и поле в title bar): комнаты, участники, сообщения (по `GET /messages?q=` — серверный поиск в бэклог сервера, пока — по загруженным); список с клавиатурой.
4. **Колонка комнат**: заголовок workspace с меню (▾: инвайт, настройки, участники, выйти), кнопка «пригласить»; категории сворачиваются (▾), у категории «+»; строка комнаты 34 px: иконка (# / 🔊 / 🔒), имя 15 px, справа при hover — «пригласить в комнату», «настройки»; непрочитанная — белый текст + пилюля слева; упоминания — бейдж. **Voice-комната**: под именем — участники (аватар 24 px + имя, зелёное кольцо у говорящего, иконки mute/deafen/стрим справа), таймер «сколько идёт разговор», `00/02` для комнат с лимитом, «LIVE» красный бейдж у стримящих.
5. **Панель «Голос подключён»** (над панелью «я»): зелёный заголовок с иконкой сигнала (уровень RTT цветом), «комната / workspace», справа — кнопка «Стрим» и «Отключиться» (красная трубка); ниже ряд из 4 крупных кнопок 56×40: Стрим экрана, Шумодав (переключатель RNNoise), Статистика, ещё (в вебе — то, что доступно). Кнопки со стеклом `toolbar`.
6. **Панель «я»**: аватар 32 со статусом, имя, вторая строка — кастомный статус/«В голосе»; справа: микрофон и наушники — кнопки с **▾ dropdown быстрого выбора устройства** (как Discord: список устройств + громкость), шестерёнка. Клик по имени — поповер профиля со сменой статуса (online/idle/dnd/invisible) и текстом статуса.

## P0 — чат

7. **Заголовок комнаты**: иконка, имя (15/600), `•`, топик (обрезка + tooltip, клик — раскрыть), справа: закреплённые, уведомления (mute комнаты), участники (toggle правой колонки), поиск в комнате.
8. **Сообщения**: аватар 40, имя 15/600 + цветной бейдж роли (OWNER/ADMIN, как «SERVER» у Discord), время 12 серым, текст 15/400 line-height 1.375; группировка последующих сообщений автора в течение 7 мин (без аватара, время при hover слева); при hover — плавающая панель действий справа (реакция, ответ, ещё ▾); ссылки — **embed-карточка** (title/description/image по OpenGraph — серверный `GET /api/unfurl?url=` в бэклог сервера, клиент готов рисовать) с цветной левой полоской; изображения — превью со скруглением 8, клик — лайтбокс; файлы — карточка иконка/имя/размер/скачать.
9. **Непрочитанное**: красная линия-разделитель «НОВОЕ» в ленте; липкий баннер сверху «N новых сообщений с <время> — Отметить прочитанными» (синий, как в Discord); при скролле вверх — кнопка «↓ к новым».
10. **Композер**: одна скруглённая полоса 44 px, слева «+» (файл; меню: файл, скриншот экрана), placeholder «Написать в #room», справа — эмодзи (пикер), отправка только при пустом поле не показывать; вложения — превью-чипы над полем с ×; typing-индикатор под полем («Bob печатает…» с анимацией трёх точек); `Shift+Enter` — новая строка; «↑» — редактировать последнее.
11. **Пустые состояния**: вместо «Выберите комнату слева» — при входе открывается последняя комната (или первая текстовая); у новой комнаты — экран «Добро пожаловать в #room» с крупной иконкой и действиями «Пригласить», «Настроить».
12. **Правая колонка участников** (240 px, скрываемая): группы «В сети — N» / «Не в сети — N», строка 42 px: аватар 32 со статусом, имя (цвет роли), вторая строка — статус/«🔊 В голосе»/«📺 Стримит»; корона у владельца; offline — 50 % прозрачности; hover — фон; клик — профиль-поповер; ПКМ — контекст-меню (громкость, mute, кик — по правам).

## P1 — голос и стрим

13. **Пикер стрима** (как Discord): модалка 900×600, сегментированный переключатель «Приложения / Весь экран», сетка превью 16:9 (2 колонки) с иконкой приложения и именем, hover — кнопка «Стримить»; внизу: слева выбранный пресет словами («Текст • 1080p • 15 fps»), справа сегмент качества (Экономия / 720p / 1080p / Оригинал — недоступные выше лимита комнаты задизейблены с подсказкой), переключатель «Текст/Видео» (contentHint), переключатель «Звук системы» (на macOS с предупреждением), шестерёнка → расширенные (кодек, статистика). Кнопка «Начать стрим» — акцентная.
14. **Просмотр стрима**: PiP 320×180 в углу чата со стеклом, имя стримера и «LIVE»; клик — развернуть в область чата с панелью: качество (Авто/слой), громкость, «в окно», «во весь экран», «закрыть»; при нескольких стримах — полоска превью снизу; у стримера — счётчик «👁 N».
15. **Voice-состояния в UI**: кольцо у аватара говорящего (зелёное, 2 px, анимация 100 мс), иконки mute/deafen у участника, серверный mute — красная перечёркнутая иконка, «подключение…» спиннер, потеря связи — жёлтый баннер в панели голоса «Переподключение…».
16. **Ошибки — только человеческие**: никаких сырых строк («Not supported», «Error: …») в UI. Каждая ошибка медиа маппится в текст + действие: «Микрофон недоступен — проверьте разрешение» с кнопкой «Открыть настройки»; в браузере без поддержки — «Ваш браузер не поддерживает …». Тосты — стекло, снизу справа, авто-скрытие 6 с, стек.

## P0.4 — чат в стиле Telegram (задача владельца, 26.09; заменяет п. 8 и 10 по внешнему виду)

36. **Лента сообщений как в Telegram Desktop**: сообщения — пузыри (bubble) с радиусом 12–16, свои — справа с акцентной заливкой (или тёмно-синим тинтом в dark), чужие — слева на поверхности `elev`; хвостик у последнего в группе; аватар 36 слева только у чужих и только у последнего сообщения группы (группировка по автору в течение 5 мин); имя автора цветное внутри первого пузыря группы; время — маленькое внутри пузыря справа-снизу (у своих — с галочками отправлено/доставлено; «часики» для optimistic); реакции — чипы под текстом внутри пузыря; ответ — цитата-полоска сверху пузыря; ссылки — карточка-превью внутри пузыря; изображения — во всю ширину пузыря (max 420 px) со скруглением, подпись под ними; файлы — иконка-кружок + имя/размер; голосовые сообщения — не делаем. Ширина пузыря ≤ 70 % ленты, max 640 px. Разделители дат — «пилюли» по центру (стекло `popover`), липкие при скролле. Фон ленты — сплошной (docs/08), опционально лёгкий узор/градиент в настройках («Внешний вид → Фон чата»).
37. **Композер как в Telegram**: скруглённое поле с автоувеличением до 6 строк, слева «📎» (меню: файл, изображение, скриншот), справа эмодзи и круглая акцентная кнопка «отправить» (появляется, когда есть текст/вложения); панель ответа/редактирования над полем с × ; превью вложений сеткой над полем; typing — в заголовке комнаты («Bob печатает…» вместо топика), как в Telegram.
38. **Контекстное меню сообщения** (ПКМ/долгое нажатие): Ответить, Копировать текст, Переслать (позже), Закрепить, Изменить, Удалить, Выбрать; реакции — быстрая строка эмодзи сверху меню. Hover-панель действий из п. 8 не нужна.
39. **Скролл и навигация**: кнопка «↓» со счётчиком непрочитанных внизу справа; «НОВОЕ» — пилюля-разделитель как дата; при открытии комнаты — прокрутка к первому непрочитанному; поиск по сообщениям — панель сверху с переходом по результатам (`GET …/messages?q=`).
40. **Плотность и шрифт**: текст 15/1.35, время 12, пузыри с внутренними отступами 8×12, между группами 8, внутри группы 2; в светлой теме свои пузыри — светло-зелёный/синий тинт, как в Telegram, чужие — белые.

## P0.5 — задачи владельца (26.09), сразу после P0

29. **Звуки событий — каждый отключается отдельно** (Настройки → Уведомления → Звуки): вход участника в мою voice-комнату, выход, мой mute / unmute, deafen / undeafen, PTT нажат / отпущен, упоминание, новое сообщение (в фоне), начало стрима, меня переместили, отключение/переподключение. У каждого — переключатель и «прослушать»; общая громкость звуков; «отключить все». Звуки короткие (≤ 300 мс), нативные по духу.
30. **Кольцо речи у говорящего** — обязательно и везде: в списке комнат под voice-комнатой (аватар 24 с зелёным кольцом 2 px), в правой колонке участников, у себя в панели «я», на плитке стримера в PiP. Источник — `ActiveSpeakersChanged`; появление сразу, исчезновение через 300 мс (docs/08 «Индикация речи»); себя — по локальному VAD/PTT.
31. **Лимит участников комнаты**: в настройках voice-комнаты «Максимум участников» (0 = без лимита, 1–99); в списке комнат индикатор `N/M` (как `00/02` в Discord) справа от имени; при заполненной комнате клик → тост «Комната заполнена»; участники с правом `MOVE_MEMBERS` (админы) входят поверх лимита. Сервер: `rooms.user_limit`, проверка в `/join` → 409 `ROOM_FULL`.
32. **Перетаскивание участников между voice-комнатами** (право `MOVE_MEMBERS`, у admin/owner по умолчанию): drag аватара участника из одной voice-комнаты в другую в списке комнат (dnd-kit), подсветка цели, курсор «нельзя» без права; также в контекст-меню участника «Переместить в… ▸». Сервер: `POST /api/rooms/{id}/voice/{userId}/move {target_room_id}` → LiveKit `MoveParticipant`; перемещённый клиент получает `RoomEvent.Moved`/`VOICE_STATE_UPDATE` и обновляет UI без переподключения; звук «меня переместили».
33. **Переименование участников админом**: контекст-меню участника → «Переименовать» (право `MANAGE_NICKNAMES`, у admin/owner) → `PATCH /api/workspaces/{id}/members/{userId} {nickname}`; ник действует в рамках workspace, виден всем; сам участник может менять свой ник, если разрешено в настройках workspace.
34. **Статус «Отошёл» (AFK)**: если нет ввода с клавиатуры/мыши ≥ 10 мин (десктоп — `powerMonitor.getSystemIdleTime()`, системно, без разрешений; веб — события активности + `visibilitychange`) → presence `idle` с жёлтой луной, как в Discord; любой ввод → `online`. Порог настраивается (5/10/15/30 мин, выкл). Ручной статус (dnd/invisible) не перебивается. В voice-комнате AFK не меняет аудио.
35. **Гостевая ссылка на комнату** (ADR-0016): настройки voice/text-комнаты → «Ссылка для гостей»: создать (срок 1 ч/1 д/7 д/бессрочно, лимит использований, права гостя: говорить / писать / файлы / стрим), копировать, отозвать; веб-страница `/r/<code>`: если залогинен — сразу в комнату; иначе экран с логотипом, названием комнаты и полем «Ваше имя» → «Войти как гость» → комната; гость видит только эту комнату, бейдж «Гость» у имени; для админа в контекст-меню гостя: «Сделать участником», «Удалить». Десктоп открывает `calaba://r/<code>`.

## v0.2 — полировка (UX-ревью 3, после v0.1)

- **Подсказка часового пояса «(+N UTC)»** обрезается вместе с именем при 256 px — сначала прятать подсказку, потом резать имя.
- **Меню участника**: отделить локальные действия («Громкость», «Заглушить для меня») от модераторских разделителем; дать «Заглушить для меня» иконку `VolumeX`.
- **Смена пароля**: поле «Текущий пароль» — первым; подзаголовок «…выйдут из аккаунта, кроме этого».
- **Кольцо фокуса после меню**: после закрытия контекстного меню, открытого мышью, не возвращать видимое кольцо на триггер (только при открытии с клавиатуры). То же для строки статуса голосовой комнаты после Enter/Esc (UX-ревью 4): кольцо только при навигации с клавиатуры.
- **Просмотр стрима**: слайдер громкости стрима по наведению; аватар-заглушка в плитках полосы превью до первого кадра.
- **Пикер стрима**: подсказка на недоступном «Оригинал» (проверить, есть ли уже).
- **Хоткеи в окне**: биндер сочетаний (#18) — расширить на остальные действия.
- **Проверка анимаций** (затухание пилюли даты, hover у PiP, тосты) — через trace/видео Playwright.
- **Переименование данных**: перенести элемент Keychain и папку userData на «Calab» с однократным копированием (сейчас намеренно «Calaba», docs/10).
- **Универсальные ссылки (AASA / App Links) — v0.2**: `apple-app-site-association` и `assetlinks.json` на app-хосте, чтобы https-ссылка `/join/…`, `/r/…` открывала установленное приложение без промежуточной карточки (п. 53).
- **Радиусы-одиночки → токены** (UX-ревью 4): icon-кнопки `rounded-[5px]` в `MessageActions.tsx`, `rounded-[4px]` в `Sidebar.tsx` → `--radius-icon`; пункты меню `rounded-[5px]` (`MessageMenu`, `MentionPopover`, `SelfPanel`, `MemberContextMenu`) и `kbd` в `TitleBar` → `--radius-row`; `code`/`pre` в Markdown — токенами.
- **Превью ссылок**: `theme_color` из unfurl, когда появится в контракте (сейчас цвет из хоста); заголовок-ссылка заметнее (акцентный цвет или цвет при наведении, не только подчёркивание).
- **Веб-карточка ссылки**: визуальный снимок превью `/r/<код>` (комната + пространство).
- **Пилюля даты «Сегодня»** перекрывает текст превью у верхнего края ленты: затухание над контентом или отступ.
- **Две лупы рядом при ≥ 1200 px** (поле поиска по пространству и ⌘F «в комнате»): у поиска в комнате — своя иконка или подсказка «Поиск в #комнате».
- **Лента и Tab**: сейчас каждое сообщение — Tab-остановка (панель действий с клавиатуры); перейти на roving-фокус стрелками ↑/↓.



## P0.6 — Элементы Discord, которых не хватает (владелец, 26.09) — до релиза

46. **Веб: компактная верхняя полоса** — 28–30 px, без резерва под светофор; ←→ слева, имя пространства по центру, справа «Упоминания» и «?»; поиск — в заголовке комнаты (п. 50). В Electron на macOS — как сейчас (38 px, светофор).
47. **Hover-панель действий у сообщения** (в дополнение к контекстному меню): справа сверху пузыря при наведении — «Реакция» (быстрые 4 + пикер), «Ответить», «Ещё…» (открывает меню). Стекло `popover`, 28 px, не перекрывает текст, появляется через 150 мс, не мешает выделению текста.
48. **Под voice-комнатой в списке** (как в Discord): строка «Статус комнаты ✎» (текст ≤ 60 символов, задаёт участник с CONNECT в комнате, виден всем, сервер: `rooms.voice_status`, `PATCH /api/rooms/{id}/voice-status`, ROOM_UPDATE) и строка «Пригласить в комнату ›» (копирует гостевую/обычную ссылку на комнату) — показываются, когда я в этой комнате.

Галочка «Всегда открывать в приложении» (localStorage, try/catch) — при заходе приложение пробуется сразу, рядом видна ссылка «Открыть в браузере». Залогиненным на вебе карточка тоже показывается. Логика решения — чистый модуль `lib/appLaunch.ts` (юнит-тесты с fake timers). Десктоп без изменений. Снимки `web-join-card`, `web-join-card-not-found` (dark/light, 960/1440) в `e2e-visual/web.spec.ts`.
54. **Кнопки-«таблетки»** (владелец, 26.09; docs/08 «Радиусы»): один токен `--radius-control: 9999px` — кнопки (primary/secondary/ghost/destructive), поля, селекты, сегментированные контролы (контур и активный сегмент), поиск, числовые поля, текстовые кнопки, чипы/бейджи (включая `N/M` у комнаты), тосты. 55. **Онбординг выверен по вертикали** (владелец, 26.09): в карточке одной высоты (488 px на окнах от 600 px, т. е. и на 960×600) три зоны — шапка (иконка, заголовок, подзаголовок) закреплена сверху, футер («Назад», «Позже», основная) прижат к низу, тело шага центрируется между ними (симметричные отступы 20). Тело есть у каждого шага, пустой карточки нет: «Микрофон» до разрешения — неактивные выбор устройства и полоса уровня с подписью; «Уведомления» — пример уведомления об упоминании; «Всё готово» — сводка «название — значение» (Микрофон: устройство / не проверен · Режим: Активация голосом / Push-to-talk · клавиша · Показ экрана (macOS): разрешён / позже · Уведомления: включены / позже). Точки прогресса, заголовки и кнопки — на одних координатах на всех шагах. Инвариант в визуальном тесте: центр тела ≈ центр области между шапкой и футером (±4 px), футер/заголовок/карточка/точки совпадают на всех шагах при высоте окна ≥ 600, композиция по центру окна (±2 px). Проверено вручную на 960×600, 1280×800, 1440×900 в обеих темах.
56. **Пустая комната и стрим** (владелец, 26.09): пустое состояние («Это начало комнаты…» + «Пригласить» / «Настроить») центрируется по вертикали в области сообщений (text и voice; с сообщениями — обычная лента). В voice-комнате, когда начинаю смотреть стрим, а в чате меньше 3 сообщений, стрим открывается развёрнутым (stage), приветствие — одной строкой под ним над композером; «Свернуть в угол» / «Развернуть» запоминаются на комнату (`prefs.streamStage`) и дальше побеждают правило. PiP-плитка — видимая рамка и более глубокая тень, чтобы не «висела» на пустом фоне. Инвариант в визуальном тесте: welcome по центру пустой ленты (±4 px) на 960×600 и 1440×800; снимок `voice-stream-empty-room`.

## v0.2 — Веб-камера (задача владельца, 26.09)

41. **Видео с веб-камеры в voice-комнате** (как в Discord): кнопка «Камера» в панели «Голос подключён» (первая в ряду, слева от «Стрим»), выбор камеры в настройках устройств и в ▾ рядом с кнопкой; превью себя перед включением (модалка «Проверьте камеру»); публикация через LiveKit как `camera`-трек: VP9/AV1 simulcast, 3 слоя (180p / 360p / 720p), `contentHint: motion`, 24–30 fps, потолки 0.15 / 0.5 / 1.5 Mbps; лимит одновременных камер в комнате (настройка, default 6); при слабой сети клиент понижает слой сам (adaptive stream), при `cpu` — 360p.
42. **Раскладка видео**: плитки участников с камерой в области чата (сетка 1–6, active speaker крупнее), рядом со стримом — стрим главный, камеры полосой; клик по плитке — развернуть; PiP-плитка камеры активного говорящего, когда чат открыт; отключение видео чужой плитки для экономии трафика (не подписываться), «Не показывать видео» в меню участника.
43. **Права и модерация**: бит `VIDEO` (1<<14; member по умолчанию да), серверный «выключить камеру» (MUTE_MEMBERS), индикатор камеры в списке комнат и колонке участников, `VoiceState.camera`.
44. **Фон и эффекты** (после базовой камеры): размытие фона (MediaPipe Selfie Segmentation в worker, только на десктопе), зеркалирование превью, «Камера при входе» — по умолчанию выключена.
45. **Сервер**: `canPublishSources` + `camera`, лимит камер в `/join` и по webhook `track_published`, `stream/request`-подобный `camera/request`, события `VOICE_STATE_UPDATE.camera`.
- Ревью v0.2 (minor): `services/camera.ts start()` — `finally` при быстром stop→start может вызвать лишний `camera/stop` и снять резерв нового старта (окно = один запрос); после SFU-move `active.reset()` не обнуляет `activeSpeaker` в store; тост app-level move не упоминает камеру, если move пришёл во время rejoin.
