# ADR-0042: Доски задач — канбан, список, таймлайн (2026-09-29)

## Контекст
Владелец: «kanban: нажимаем как календарь — интерфейс меняется: слева наши доски, справа канбан, можно
переключить списком; таймлайн типа Ганта, чтобы планировать, что когда, дедлайны; борды разграничивать,
кому можно видеть — ролевая модель, гибко и красиво, как в Linear (скрины); комменты внутри таски
обязательно». Ориентир — Linear: карточки с ключом `FNG-98`, статусы с типами (backlog / todo / in
progress / done / canceled), приоритет, исполнитель, лейблы, свойства справа, лента активности с
комментариями, таймлайн проектов с линией «сегодня».

## Решение

### 1. Модель
```
boards            id, workspace_id, name (1..60), key (2..6 A–Z0–9, UNIQUE в пространстве; «FNG»), emoji/icon_file_id?,
                  description (≤ 2000), is_private, position, next_number (счётчик ключей), created_by,
                  created_at, archived_at
board_permissions board_id, target_type ('role'|'user'), target_id, allow bigint, deny bigint   -- как room_permissions
board_statuses    id, board_id, name (1..32), type ('backlog'|'unstarted'|'started'|'completed'|'cancelled'),
                  color, position, is_default (одна на доску, для новых задач)
board_labels      id, board_id, name (1..32), color, position                    (≤ 50 на доску)
board_milestones  id, board_id, name (1..60), due_on (date), position             (ромбы на таймлайне, ≤ 50)
tasks             id, board_id, number (UNIQUE (board_id, number); ключ = board.key || '-' || number),
                  title (1..200), description (markdown-lite ≤ 20000), status_id, priority (0 none|1 low|2 medium|
                  3 high|4 urgent), assignee_id?, created_by, estimate? (1..21), start_on? (date), due_on? (date),
                  parent_id? (подзадача, один уровень), milestone_id?, position (double, дробный порядок внутри
                  статуса), room_id → rooms (type='task', workspace_id, создаётся вместе с задачей),
                  created_at, updated_at, completed_at?, archived_at?
task_labels       task_id, label_id                                              PK
task_relations    task_id, related_id, kind ('blocks'|'relates'|'duplicates'), created_by     -- blocks хранится
                  один раз: task blocks related; UNIQUE (task_id, related_id, kind)
task_attachments  task_id, file_id (UNIQUE), position                              (≤ 20; в описании)
-- комментарии = сообщения скрытой комнаты задачи (см. ниже): tasks.room_id → rooms(type='task')
task_activity     id, task_id, actor_id, kind ('created'|'status'|'assignee'|'priority'|'labels'|'dates'|'estimate'|
                  'parent'|'milestone'|'relation'|'title'|'archived'|'restored'), before jsonb, after jsonb, created_at
task_subscribers  task_id, user_id, muted bool                                   PK  -- автор, исполнитель,
                  комментаторы и упомянутые подписываются автоматически; «Отписаться» = muted
```
**Комментарии — это сообщения** (владелец: «прикрепить документы, реакции, стикеры — всё как в чате, Linear
+ Telegram»): у каждой задачи скрытая комната `rooms.type = 'task'` (не в списке комнат, не в READY
`rooms`, без голоса), и лента задачи — обычные `messages` этой комнаты со всем чатовым: вложения, реакции,
стикеры, голосовые, правка/удаление, ответы, `@`-упоминания, пересылка (в задачу и из задачи), закрепы,
поиск, прочитанность и typing — тот же путь `/api/rooms/{room_id}/messages*`, как у DM и «Заметок»
(ADR-0039). Права комнаты выводятся из прав доски (`RoomAccess.Task`): `VIEW_BOARD` → `VIEW_ROOM |
SEND_MESSAGES | ATTACH_FILES`, `EDIT_TASKS` → `+ MANAGE_MESSAGES`; override комнаты не используются.
Файлы задач и комментариев — те же `files` (квота пространства). Удаление задачи — `archived_at`
(«Архивировать»; из архива можно восстановить), окончательное удаление — только вместе с доской.
Задачи в статусах `completed`/`cancelled` старше 30 дней архивируются метёлкой раз в час
(настройка доски `auto_archive_days`, 0 = никогда) — доска не тяжелеет.

### 2. Права (ADR-0008, ADR-0026) — новые биты `permissions.proto`
```
PERMISSION_VIEW_BOARD    = 1 << 17   видеть доску, задачи, комментарии; комментировать; подписываться
PERMISSION_CREATE_TASKS  = 1 << 18   создавать задачи; править свои и назначенные на себя (все поля, кроме архива чужих)
PERMISSION_EDIT_TASKS    = 1 << 19   править, двигать, архивировать любые задачи и чужие комментарии (модерация)
PERMISSION_MANAGE_BOARD  = 1 << 20   статусы, лейблы, вехи, настройки, доступ, архив доски
```
Дефолты ролей: owner/admin — все; member — `VIEW_BOARD | CREATE_TASKS`; guest — ничего. Доска, как
комната: `board_permissions` — override по роли и пользователю; `is_private` — видят только те, у кого
`VIEW_BOARD` по override (как приватная комната). `computePermissions` не меняется — та же функция с
override доски; в `ROOM_ONLY` не входят (биты доски применяются только к доскам, в комнатах игнорируются:
добавить в `BOARD_ONLY`, зеркально Go/TS, тест-векторы `proto/testdata/permissions.json`). Всё проверяется
на сервере; клиент лишь прячет UI. Пространство: `MANAGE_WORKSPACE` создаёт доски; создатель получает
override `MANAGE_BOARD` на свою доску. UI доступа — как у комнаты («Доступ»: роли и участники, allow/deny).

### 3. API (`docs/04`, `boards.proto`; префикс `/api`)
- Доски: `GET /workspaces/{id}/boards` (видимые), `POST /workspaces/{id}/boards {name,key,emoji,is_private}`,
  `GET/PATCH/DELETE /boards/{id}` (DELETE = архив; `?purge=1` — окончательно, `MANAGE_BOARD`), `PUT
  /boards/{id}/position`, `GET/PUT /boards/{id}/permissions` (как у комнат), статусы/лейблы/вехи:
  `POST/PATCH/DELETE /boards/{id}/{statuses|labels|milestones}[/{sid}]` (удаление статуса требует `move_to`).
- Задачи: `GET /boards/{id}/tasks?status&assignee&label&priority&q&archived&updated_after&cursor` (≤ 500 за
  страницу; клиент грузит доску целиком постранично, кроме архива), `POST /boards/{id}/tasks` (title,
  description, status_id?, priority, assignee_id, label_ids, start_on, due_on, estimate, parent_id,
  milestone_id, `after_task_id?` для позиции, `from_message_id?` — «Создать задачу из сообщения»: описание
  получает цитату и ссылку на сообщение), `GET /tasks/{id}` (полная: лейблы, подзадачи, связи, вложения,
  подписка), `GET /t/{KEY-N}` → redirect/lookup по ключу, `PATCH /tasks/{id}` (любое поле; `status_id` +
  `after_task_id`/`before_task_id` = перенос в канбане; изменения пишут `task_activity`), `POST
  /tasks/{id}/archive|restore`, `PUT /tasks/{id}/relations {related_id, kind}` / `DELETE`, `PUT
  /tasks/{id}/subscription {muted}`, вложения через `POST /boards/{id}/files` (как `rooms/{id}/files`).
- Комментарии: сообщения комнаты `task.room_id` через существующие `/rooms/{room_id}/messages*`, реакции,
  стикеры, файлы, поиск; лента задачи = `GET /tasks/{id}/activity?before&limit` — `TaskActivityItem { oneof:
  Message | TaskActivity }` одной лентой по времени; упоминания `@<user_id>` как в сообщениях → уведомление и
  подписка на задачу.
- Мои задачи: `GET /me/tasks?workspace_id&scope=assigned|created|subscribed&open=1`.
- Поиск: `q` — `tsvector` по `title`+`description` (+ trigram по ключу); в ⌘K — по всем видимым доскам.
- **Боты — как пользователи** (владелец: «боты должны получать права на доски как юзеры: читать список
  досок, задачи, искать, записывать, менять»): бот — участник пространства с ролями, `computePermissions`
  считается для него так же, override доски может целить бота как пользователя; `botAllow` на все
  маршруты досок и задач (список, чтение, поиск, `POST`/`PATCH` задач, комментарии через комнату задачи,
  статусы/лейблы/вехи при `MANAGE_BOARD`), кроме `PUT /boards/{id}/permissions` и `?purge=1` (только люди).
  Бот-SDK (`packages/bot-sdk`) получает методы `boards.list/get`, `tasks.list/search/get/create/update`,
  `tasks.comment`.

### 4. События gateway (`docs/05`; канал `board:<id>`, доставка тем, кто видит доску — как у комнат)
`BOARD_CREATE = 75`, `BOARD_UPDATE = 76` (в т. ч. статусы/лейблы/вехи/архив/доступ → клиент перечитывает
права), `BOARD_DELETE = 77`, `TASK_CREATE = 78`, `TASK_UPDATE = 79` (полная задача без ленты; `position`
включён), `TASK_DELETE = 80` (архив/purge), `TASK_ACTIVITY = 81` (одна запись). Комментарии идут обычными
`MESSAGE_CREATE/UPDATE/DELETE`, реакции — `REACTION_*` по комнате задачи (подписка на `room:<task.room_id>` у
тех, кто видит доску; клиент подписан на комнаты открытых задач и на непрочитанность «моих» задач). READY: `WorkspaceSnapshot.boards[]` (id, name, key, emoji,
is_private, position, `permissions` для смотрящего, счётчик открытых «моих»). Уведомления (модель
`notifications`, `proto/testdata/notifications.json`): назначили на меня, упомянули в задаче/комментарии,
комментарий в задаче, на которую я подписан, изменение статуса моей задачи → пункт «Задачи» в
настройках уведомлений (`all|mentions|none`, по умолчанию `all`), системное уведомление и бейдж на
иконке досок в шапке (число непрочитанных по задачам, как `mention_count`).

### 5. Клиент (`docs/08` «Доски»; ориентир — Linear)
- **Режим «Доски»**: иконка в шапке колонки (рядом с календарём, бейдж непрочитанных). Клик — интерфейс
  переключается: левая колонка → список досок пространства (эмодзи + название, «Мои задачи» сверху, «+ Доска»
  для `MANAGE_WORKSPACE`, перетаскивание порядка, ⋯ → настройки/доступ/архив), центр → выбранная доска;
  повторный клик или Esc — обратно к комнатам (состояние доски и фильтров сохраняется). Панель участников
  справа скрыта; вместо неё — **панель задачи** при открытой задаче.
- **Шапка доски**: название, переключатель вида `Канбан | Список | Таймлайн` (segmented), фильтры
  (исполнитель, лейбл, приоритет, статус, «мои», текст), группировка (для списка: статус/исполнитель/
  приоритет/лейбл/веха), «Показывать завершённые», «+ Задача» (`C`), ⋯ (настройки доски, архив, экспорт CSV).
  Фильтры и вид — на пользователя и доску (`localStorage`), в URL-состоянии.
- **Колонки и лейблы настраиваются на месте** (владелец: «настраивать статусы, колонки для каждого борда
  как-то удобно; лейблы тоже»): заголовок колонки — двойной клик переименовывает, ⋯ → цвет, тип
  (backlog/todo/в работе/готово/отменено), «Скрыть», «Удалить» (с выбором, куда перенести задачи), «Сделать по
  умолчанию»; колонки перетаскиваются за заголовок; «+ Колонка» справа. Пикер лейблов на карточке и в панели —
  поиск, «Создать лейбл «…»» на лету с выбором цвета, ⋯ у лейбла → переименовать/цвет/удалить; полный
  редактор — в настройках доски (те же компоненты). Шаблон статусов при создании доски: «Простая»
  (Todo / В работе / Готово), «Разработка» (Backlog / Todo / В работе / Ревью / Готово / Отменено), «Пустая».
- **Канбан**: колонки = статусы (цвет и иконка типа, счётчик, «+» внизу, скрыть колонку → «Скрытые» справа как в
  Linear), карточка: ключ, иконка статуса, заголовок (2 строки), чипы лейблов, приоритет, срок (красный, если
  просрочен), аватар исполнителя, счётчик подзадач/комментариев. **D&D**: карточку между колонками и внутри
  (дробная `position`; оптимистично, откат при ошибке), участника из ⌘K/списка на карточку — назначить,
  лейбл на карточку; клавиши: `C` — новая, `E` — правка, `S` — статус, `A` — исполнитель, `P` — приоритет,
  `L` — лейбл, `D` — срок, `Delete` — архив, `⌘↩` — сохранить, `↑↓` — по карточкам. Контекстное меню
  карточки повторяет клавиши. Виртуализация колонок > 200 карточек.
- **Список**: строки, сгруппированные (по умолчанию по статусу), сортировка (обновлено/срок/приоритет/
  ключ), inline-правка статуса/приоритета/исполнителя/срока прямо в строке, мультивыбор (Shift/⌘) и
  массовые действия (статус, исполнитель, лейбл, архив).
- **Таймлайн** (Гант): слева список задач (только с датами; без дат — свёрнутый блок «Без дат», из которого
  задачу тянут на шкалу), справа шкала (масштаб неделя/месяц/квартал, линия «сегодня», выходные серые),
  полосы задач цветом статуса, **D&D**: тянуть полосу — перенос, за края — изменение начала/конца, из
  «Без дат» — назначить даты; вехи — ромбы (тянутся); связь `blocks` — красная метка на полосе, если
  блокирующая задача заканчивается позже начала зависимой; группировка по исполнителю/вехе; клик по полосе
  — панель задачи.
- **Панель задачи** (справа, ширина как панель участников × 2, `⌘\` разворачивает на весь центр): заголовок
  (inline), ключ + «Копировать ссылку», описание (markdown-lite, тот же редактор, что в чате, с вложениями и
  превью), подзадачи (список с чекбоксами + «Добавить»), связи («Блокирует / Заблокирована / Связана» +
  пикер задач), справа свойства: статус, приоритет, исполнитель, лейблы, даты (начало/срок), оценка, веха,
  родитель; **лента активности**: комментарии и изменения одной лентой (как в Linear), комментарии — тот же
  `ChatPane`/композер, что в чате (вложения, реакции, стикеры, голосовые, ответы, правка, `@`-упоминания,
  `⌘↩`); «Подписаться/Отписаться»; ⋯ → архив, дублировать, переместить
  на другую доску (`MANAGE_BOARD` на обеих).
- **Создание**: диалог (заголовок, описание, свойства в строке чипов как в Linear, «Создать ещё»),
  `C`/«+ Задача»/«+» в колонке (со статусом колонки)/из «Без дат»; **из сообщения** — пункт меню сообщения
  «Создать задачу» → диалог с заголовком из текста и ссылкой на сообщение в описании.
- **Ссылки**: `/b/<board_id>` и `/t/<KEY-N>` — deep link (десктоп/веб); в чате ссылка на задачу разворачивается
  карточкой (ключ, заголовок, статус, исполнитель) — unfurl своих ссылок без HTTP, по правам смотрящего.
- **Настройки доски**: основное (название, ключ — менять нельзя после первой задачи, эмодзи, описание,
  автоархив), статусы (список с типами, цветами, перетаскиванием; удаление с переносом), лейблы, вехи,
  доступ (как у комнаты), архив/удаление (подтверждение вводом ключа).
- **Мобильный веб**: доски в шторке, по умолчанию «Список», канбан — колонки горизонтальным свайпом, панель
  задачи — полноэкранно, таймлайн — только чтение с прокруткой.
- **Производительность**: стор нормализован (`tasks by id`, `order by status`), строки/карточки `memo`,
  drag-состояние локально, стор пишется на drop; событие `TASK_UPDATE` перерисовывает одну карточку;
  таймлайн рисует только видимый диапазон; профиль `perf-call.ts` в режиме доски во время звонка.

### 6. Лимиты и тариф
≤ 50 досок на пространство, ≤ 20 статусов, ≤ 50 лейблов и вех на доску, ≤ 5000 активных (неархивных)
задач на доску (дальше — 409 `BOARD_TASK_LIMIT`, подсказка про архив), ≤ 200 подзадач у родителя,
комментарий ≤ 4000, описание ≤ 20000. Тарифы: Free — 3 доски, Team/Enterprise — без ограничения
(`plans.Limits.max_boards`; лендинг и docs/16 — строка «Доски задач»).
