# ADR-0050. Веб-приложения пространства (ярлыки сайтов в рейле)

Статус: принято (2026-09-30). Владелец, 30.09: «под пространство добавлять аппки (url-адреса просто):
у админов плюсик мелкий, появляется окно, куда можно залить картинку и url указать; при переключении
появляется тот сайт, который там вбили, чтобы можно было разного рода аппки втыкать».

## Решение

### 1. Модель и права
- Таблица `workspace_apps` (миграция — следующий свободный номер): `id`, `workspace_id`, `name` (1..40),
  `url` (≤ 2048), `icon_file_id` (картинка через существующую загрузку файлов, как иконка пространства;
  без картинки — первая буква названия на цветной плашке), `position` (float, порядок), `created_by`,
  `created_at`, `updated_at`. ≤ 20 на пространство.
- Управляет (добавить/изменить/удалить/переставить) — `MANAGE_INTEGRATIONS` (ADR-0048: «будущие
  интеграции»). Видят — все участники пространства, **не гости**. Боты — нет. Без новых битов.
- URL: только `https://`; `http://` — только для частных адресов (localhost, 10/8, 172.16/12, 192.168/16,
  `*.local`, одиночное имя без точки) — интранет. Сервер валидирует схему и хост; сам по URL **не ходит**
  (нет SSRF: страницу грузит клиент).

### 2. Контракт
`proto/calaba/v1/workspace.proto` (или отдельный `apps.proto`): `WorkspaceApp { id, workspace_id, name, url,
icon_file_id, icon_url, position, created_by, created_at, updated_at }`. REST: `GET /api/workspaces/{id}/apps`,
`POST` (create), `PATCH /api/workspace-apps/{id}`, `DELETE`, `PUT …/position`. В READY — список приложений
каждого пространства (их мало). События gateway: `WORKSPACE_APP_UPSERT`, `WORKSPACE_APP_DELETE` в канал
пространства (следующие свободные номера).

### 3. Клиент — рейл и экран
- Рейл: под иконкой **активного** пространства — столбик иконок его приложений (32 px, скругление как у
  пространств, подсказка с названием), под ними у `MANAGE_INTEGRATIONS` мелкий «+» (24 px, `text-muted`).
  Приложения других пространств не показываются. Перетаскивание иконок — порядок (D&D обязателен), правый
  клик — «Изменить / Открыть в браузере / Перезагрузить / Удалить» (управление — по праву).
- «+» / «Изменить» — диалог (Modal 400): иконка (загрузка картинки с кадрированием в квадрат, как у
  пространства), «Название», «Адрес» (подставляет `https://`, проверка по правилу §1), «Сохранить».
- Выбор приложения: колонка комнат и контент заменяются сайтом на всю ширину; сверху тонкая полоса
  (32 px): иконка + название, ◀ ▶ ⟳, «Открыть в браузере», домен текущей страницы. Рейл, островок и
  голосовая полоса остаются — звонок не прерывается. Клик по пространству — назад к его комнатам.

### 4. Безопасность встраивания (Electron) — главное
- Сайт открывается в **`WebContentsView`** из main-процесса, не в `<webview>` и не в iframe renderer'а:
  `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, **без preload**, `webSecurity: true`.
  Renderer приложения Calab не получает доступ к содержимому сайта и наоборот; IPC у вью нет.
- Отдельная постоянная сессия на приложение: `session.fromPartition('persist:app-<appId>')` — логины на
  сайтах сохраняются, но изолированы от Calab и от других приложений (cookie нашего API туда не
  попадают). Удаление приложения чистит его partition.
- Разрешения (`setPermissionRequestHandler`): камера/микрофон/уведомления/геолокация/clipboard-read —
  по запросу с диалогом Calab «Сайт X просит доступ к микрофону» (запоминается на приложение); всё прочее
  (HID, serial, USB, MIDI sysex, pointer lock вне фуллскрина) — запрет. `setDisplayMediaRequestHandler` — запрет.
- Навигация: внутри вью разрешена любая https (сайты уходят на SSO и возвращаются). `window.open`:
  тот же сайт/OAuth-попап — дочернее окно Calab с тем же partition и теми же ограничениями; прочее —
  системный браузер. Схемы кроме http/https (file:, javascript:, calab:, custom) — запрет; `will-download` —
  диалог сохранения ОС.
- Никаких `executeJavaScript`, `insertCSS`, чтения DOM сайта из Calab.
- Существующие guards (`installWebContentsGuards`) для окна приложения не ослабляются: у вью — свой набор.

### 5. Производительность (CLAUDE.md, docs/14)
- Создаётся при первом открытии; при уходе на пространство вью скрывается (`setVisible(false)`,
  `backgroundThrottling: true`) и **держится живым** не больше 2 последних приложений (LRU), остальные
  уничтожаются (память на слабых машинах). Свёрнутое/скрытое окно Calab — вью тоже скрыты.
- Никаких таймеров в renderer для приложений; полоса навигации обновляется по событиям вью.

### 6. Веб-клиент
`<iframe sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox
allow-downloads">` с `referrerpolicy="no-referrer"`. Многие сайты запрещают встраивание
(`X-Frame-Options`, `frame-ancestors`) — клиент не может это узнать надёжно, поэтому поверх фрейма
через 4 с без `load` и всегда в полосе — «Открыть в новой вкладке»; на телефоне приложение сразу
открывается в новой вкладке. CSP веб-клиента: `frame-src https:` только для этого фрейма (без `http:` — на https-странице это mixed content; второе ревью)
(Caddyfile/мета) — согласовать с текущей CSP.

## Последствия
- Протокол и Electron-безопасность — второе ревью обязательно.
- Отложено: видимость по ролям, приложения в DM/личные, авто-иконка (favicon) — сервер не ходит по URL,
  бейджи непрочитанного у сайтов, горячие клавиши.

Уточнение ниже в части нижнего островка заменено [ADR-0053](0053-workspace-app-full-height.md).

## Уточнение (2026-09-30, владелец: «убери нижний островок и полосу инструментов»)
Экран приложения — во весь остров до нижнего края окна: §3 «тонкая полоса 32 px» убрана, вместо неё
линия загрузки 2 px над сайтом (конечная анимация, только пока грузится). Нижний островок (профиль,
микрофон) при открытом приложении не показывается, **кроме звонка**: пока идёт голос, островок
остаётся, и сайт уступает ему полосу (`--island-height`, как и раньше). Навигация без кнопок:
⌘/Ctrl+[ и ] (назад / вперёд), ⌘/Ctrl+R (перезагрузить) при фокусе в сайте — обработчик
`before-input-event` вью в main; меню плитки в рейле («Перезагрузить», «Открыть в браузере»). В
заголовке окна вместо переключателя пространства — название приложения (без «⌄»), пока оно открыто.
Границы вью по-прежнему считает main из прямоугольника, присланного renderer'ом (ResizeObserver) —
появление/исчезновение островка меняет высоту области и приходит обычным `setBounds`. Веб-клиент: то
же (без полосы; «Открыть в новой вкладке» — оверлей при блокировке фрейма и меню плитки).
