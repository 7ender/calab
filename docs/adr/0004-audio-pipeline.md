# ADR-0004: Аудио-пайплайн (2026-09-25)

## Решение
- Opus mono, битрейт — настройка комнаты (16–64 kbps, по умолчанию 32; дефолт задаётся на workspace), DTX on, Opus in-band FEC on.
- RED по умолчанию **выключен** — opt-in переключатель «нестабильная сеть» в настройках (удваивает аудио-трафик; FEC покрывает типичные потери).
- Эхоподавление — Chromium AEC3 (штатное), удалённый звук воспроизводится **только** через `<audio>`-элементы; `webAudioMix: false`; никакой обработки remote-аудио через WebAudio.
- Шумоподавление — RNNoise в AudioWorklet поверх AEC3; его же VAD используется для voice activation (гистерезис, hangover 400 мс). Пока RNNoise включён, встроенный `noiseSuppression` выключен (нет двойной обработки); RNNoise выключен → встроенный включён.
- PTT — `uiohook-napi` в main (keydown/keyup); на Wayland — портал GlobalShortcuts где есть.
- Системный звук стрима — только если платформа умеет исключать собственный процесс (`restrictOwnAudio` / SCK `excludesCurrentProcessAudio`), иначе выключен по умолчанию.

## Почему
AEC3 берёт референс только со звука, выведенного самим WebRTC (crbug 687574) — любой WebAudio-микс на выходе ломает эхоподавление. Loopback Windows захватывает голоса участников и возвращает их в комнату.

## Последствия
- Нет стерео-панорамирования и эквалайзера на remote-звуке.
- Обязательные ручные тесты эха на 3 машинах перед каждым релизом, меняющим аудио.
