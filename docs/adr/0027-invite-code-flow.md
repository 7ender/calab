# ADR-0027: Один код приглашения для регистрации и вступления (2026-09-27)

## Контекст
Прод (`REGISTRATION_MODE=invite`, docs/09 #36): приглашённый по почте открывал «Принять приглашение» и попадал на регистрацию с пустым обязательным «Кодом приглашения» (клиент читал код из ссылки один раз при монтировании формы — код терялся, если форма уже была на экране); код email-приглашения в диалоге «Присоединиться» давал «не найден» (после автовступления он израсходован); поверх онбординга висел диалог вступления. По ADR-0023 код из письма при регистрации сразу помечал адрес подтверждённым — то есть утёкший/пересланный код давал чужой адрес «подтверждённым».

## Решение
1. **Один код.** Код email-приглашения (`workspace_invites.code`, привязан к адресу) и код ссылки — оба валидный `invite_code` регистрации, оба работают в `GET /api/invites/{code}` и `POST /api/invites/{code}/join`.
2. **Email-код не доказывает адрес.** Регистрация с ним: адрес должен совпасть (иначе `403 INVITE_EMAIL_MISMATCH`), аккаунт создаётся неподтверждённым, код не расходуется; вступление — после подтверждения адреса кодом из письма (`AcceptEmailInvites`). `POST /api/auth/verify` → `VerifyEmailResponse {me, joined_workspace_ids}` (+ `WORKSPACE_CREATE`). `POST /api/invites/{code}/join` с email-кодом: чужой адрес — `403 INVITE_EMAIL_MISMATCH`, неподтверждённый — `403 EMAIL_NOT_VERIFIED`. Без SMTP (приглашение создано до отключения почты) — прежнее поведение: код = доказательство.
3. **Повторное открытие.** Принятое email-приглашение остаётся в превью до истечения; участник по тому же коду получает членство (200), остальные — mismatch / `INVITE_INVALID`.
4. **Код ссылки** — вступление сразу при регистрации (как раньше).
5. **Письмо** — 3 шага и «Код приглашения: …» текстом как запасной путь.

## Последствия
- На один шаг больше для приглашённого по почте (код подтверждения), зато единый путь «доказать адрес → вступить» и нет «подтверждённых» чужих адресов по утёкшему коду.
- Клиент: код из ссылки — реактивное состояние (`stores/invite.ts`), на форме — карточка «Приглашение в «…»» вместо поля; онбординг без шага «Присоединиться» после регистрации по приглашению.
