# ADR-0005: Кодек и доставка стрима экрана (2026-09-25)

## Решение
- AV1 основной, **без `backupCodec`** (клиент только Electron — один декодер у всех); `contentHint: 'detail'` (переключатель `motion`).
- SVC по `contentHint`: `detail` → `L1T3` (текст всегда резкий, SFU срезает fps медленным зрителям), `motion` → `L3T3_KEY`. Цена: превью `detail`-стрима через adaptive stream — полное разрешение с низким fps. Компромисс `L2T3_KEY` замеряем в медиа-спайке (docs/07, этап 1).
- Пресеты: economy 720p5 / 720p15 / 1080p15 / original30; потолки 0.4 / 1.0 / 2.0 / 4.0 Mbps. Потолок ≠ расход: статичный контент — 50–300 kbps. Зритель получает слой под свою полосу (SVC + TWCC), независимо от пресета автора.
- `dynacast: true`, `adaptiveStream: true`; зритель подписан только на видимые стримы; превью тянет низкий слой (для `motion`; для `detail` — низкий fps).
- Лимит 3 стрима в комнате — на сервере.
- H.264 (hw) — запасной вариант для пресета original при `qualityLimitationReason: cpu`.

## Почему
AV1 в libwebrtc со screen-content tools на ~45 % эффективнее VP9 по тексту; SVC позволяет SFU отдавать разные слои без перекодирования; adaptive stream + отсутствие лишних подписок сокращают исходящий трафик SFU в 3–5 раз (с ~435 до ~75–150 Mbps на 30 зрителей и 3 стрима).

## Риски
Software AV1 на 1440p+ 30fps — нагрузка 1–2 ядра; проверить на реальных ноутбуках.
