# ADR-0034: Звонки один на один (2026-09-28)

## Контекст
Владелец (0.8.0): «выбрать пользователя и позвонить ему: окно как при вызове на iPhone, дозвон в
модалке; у собеседника уведомление — поднять или скинуть; в контекстном меню участника «Позвонить»
и «Написать» наверху; в DM — трубка в шапке; пока человек говорит, в группе видно, что он на
звонке; микрофон только по голосу, без push-to-talk». Сегодня голос есть только в голосовых
комнатах пространства (ADR-0012/0019), DM — комната без пространства и без голоса (ADR-0020).

## Решение
1. **Звонок = голосовая сессия в DM-комнате.** LiveKit-комната `dm:<room_id>`, участники — только
   двое из `dm_members`. Весь медиастек тот же (`services/voice.ts`, эхоподавление docs/02,
   `RemoteAudioOut`, камера/показ экрана как в комнате, StatsOverlay). `POST /api/rooms/{id}/join`
   для DM-комнаты выдаёт токен только участнику **активного** звонка этой DM (иначе 409
   `CALL_NOT_ACTIVE`); гранты — publish audio/video/screen, subscribe; лимиты тарифа комнат не
   применяются (двое); `VoiceState` DM-комнат рассылается по `user:<id>` обоим (как события DM),
   в пространства не попадает.
2. **Сигналинг — сервер + gateway, состояние в Redis** (сервер stateless): `call:<id>` = `{id,
   dm_room_id, caller_id, callee_id, state, created_at, answered_at, ended_at, reason}`, TTL 24 ч;
   индекс `user_call:<uid>` → id активного/звонящего звонка (для «занят» и presence). Состояния:
   `RINGING → ACTIVE → ENDED`, `RINGING → DECLINED | CANCELLED | MISSED | BUSY`, `ACTIVE → ENDED`.
   - `POST /api/dms/{id}/call` — участник DM, правило «можно писать» (`canDm`: общее пространство,
     не бот, не заблокирован), у вызываемого нет `user_call` (иначе 409 `BUSY` — без звонка, но
     запись в лог п. 5), у звонящего нет (409 `IN_CALL`). Ответ 201 `{call}`; события:
     `CALL_RING {call, caller: User}` → `user:<callee>`, `CALL_STATE {call}` → обоим.
   - `POST /api/calls/{id}/accept` (вызываемый, только RINGING) → ACTIVE, `CALL_STATE` обоим
     (все устройства вызываемого прячут входящий; принявшее делает `join`). `…/decline`
     (вызываемый) → DECLINED; `…/cancel` (звонящий, RINGING) → CANCELLED; `…/hangup` (любой,
     ACTIVE) → ENDED с длительностью.
   - **Таймаут дозвона 45 с** — таймер на инстансе, создавшем звонок, плюс общий тик (15 с, как у
     статусов) для подстраховки → MISSED. **Обрыв**: `participant_left`/`room_finished` LiveKit по
     `dm:*` без переподключения за 30 с → ENDED `reason: "lost"` (переподключение — как в
     комнатах, ADR-0019). Выход из приложения = hangup (клиент шлёт при закрытии; иначе LiveKit).
3. **Presence «на звонке».** `Presence.on_call bool` (новое поле), выставляется на ACTIVE и
   снимается на ENDED, рассылается `PRESENCE_UPDATE` во все пространства пользователя — с кем
   говорит, не раскрывается. Клиент: иконка трубки после имени и подпись «На звонке» в списках
   участников/профиле (как «в голосе», docs/08). В голосовой комнате пространства это не нужно —
   там и так видно.
4. **Занятость и голосовая комната.** Если вызываемый в голосовой комнате пространства — звонок
   идёт (не BUSY); принимая, клиент сам выходит из комнаты и подключается к звонку. Звонящий,
   находясь в комнате, при нажатии «Позвонить» получает подтверждение «Выйти из комнаты и
   позвонить?». Два звонка одновременно невозможны (`user_call`). Второй входящий во время
   разговора → сервер отвечает BUSY звонящему, вызываемый видит только запись в логе DM.
5. **Лог звонков в DM** — системное сообщение `SystemMessage.call` (`CallCard {caller_id, outcome
   ENDED|MISSED|DECLINED|CANCELLED|BUSY, duration_sec, started_at}`) при завершении; в ленте —
   строка как в Telegram: «Исходящий звонок · 5:12» / «Пропущенный звонок» (у вызываемого —
   красным, считается непрочитанным DM и даёт системное уведомление «Пропущенный звонок от X»).
6. **Клиент.**
   - Хранилище `stores/call.ts` (`{call, phase: idle|outgoing|incoming|active, since}`), сервис
     `services/call.ts`: REST + обработка `CALL_RING`/`CALL_STATE`, повторная доставка при
     RESUME (`READY.call` — текущий звонок пользователя, чтобы после реконнекта состояние
     восстановилось), `join` через `voice.join(dmRoomId, {call: true})`.
   - **Исходящий**: модалка «как на iPhone» — крупный аватар, имя, «Вызов…» с анимацией трёх
     точек (конечная, `prefers-reduced-motion`), кнопка «Отменить» красная круглая; гудок
     `call-outgoing` (loop ≤ 45 с через `<audio>`, громкость уведомлений). При ACTIVE модалка
     закрывается, дальше обычный in-call UI: шапка DM показывает «Звонок · 00:42» (таймер —
     листовой компонент `useNow`) и красную «Завершить»; нижний островок/мобильная полоса —
     те же, что в комнате (микрофон, звук, камера, экран, статистика). Модалка не блокирует
     чат: свернуть в плашку «Вызов… · Отменить» вверху окна можно кликом вне.
   - **Входящий**: модалка поверх всего (аватар, имя, «Входящий звонок», зелёная «Принять»,
     красная «Отклонить»), рингтон `call-incoming` loop; при DND — без звука, модалка
     показывается; окно скрыто/не в фокусе → системное уведомление «Входящий звонок от X»
     (клик — фокус окна с модалкой; кнопки действий в уведомлении не используем — нет во всех
     ОС). Все устройства звонят; принятие/отклонение на одном закрывает у остальных.
   - **Микрофон в звонке — только по голосу**: `voice.join(..., {call: true})` принудительно
     `micMode = 'voice'` на время звонка, PTT-биндинг не активируется, в островке нет подсказки
     PTT; после звонка настройка пользователя восстанавливается.
   - **Точки входа**: контекстное меню участника — первые два пункта «Позвонить» (`Phone`) и
     «Написать» (`MessageCircle`), затем «Профиль»…; профиль — кнопки «Написать» и «Позвонить»;
     шапка DM — иконка трубки слева от меню «⋯»; ⌘K строка человека — кнопка «Позвонить» рядом с
     «Написать». Себе, ботам и тем, кому нельзя писать, «Позвонить» не показывается.
   - Мобильный веб: модалки на весь экран, полоса звонка внизу как в голосе; фоновые вкладки не
     звонят (ограничение веба, docs/09).
7. **Bot API**: боты не звонят и не принимают (403); `CallCard` бот получает как системное
   сообщение DM.

## Последствия
- Протокол: `call.proto` (`Call`, `CallState`, `CallOutcome`, запросы/ответы), `SystemMessage.call
  = 3`, `Presence.on_call`, события `CALL_RING/CALL_STATE` (46, 47), `READY.call`. Второе
  security-ревью обязательно (LiveKit-гранты для DM, `join` по звонку, presence).
- docs/02 «Звонки» (тот же аудиотракт, VAD принудительно), docs/04 «Звонки» (Redis-ключи, лог),
  docs/05 события и `READY.call`, docs/08 «Звонок» (модалки, шапка, presence), docs/16 строки
  `dms/{id}/call`, `calls/*`, docs/19 (боты), docs/09 #85.
- Интеграционные тесты: полный цикл ring→accept→join→hangup с логом и presence; decline;
  cancel; таймаут → MISSED (тик с укороченным таймаутом в тесте); BUSY; join DM без звонка → 409;
  не-участник DM → 404; бот → 403; повторный accept → 409; RESUME отдаёт текущий звонок.
- Версия 0.8.0.
