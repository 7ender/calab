# ADR-0041: Календарь — фильтр по людям, подбор времени, CalDAV (2026-09-29)

## Контекст
Владелец после 1.0.0: «фильтры по людям + подбор окна (выбрать одного или несколько человек), чтобы
посмотреть, где свободные слоты; ещё, может быть, интеграцию с CalDAV у пользователя». И: «когда нажимаю
иконку календаря — открывать текущий день сразу».

## Решение
1. **Свободно/занято (сервер).** `GET /api/workspaces/{id}/freebusy?users=<id,…>&from&to` (окно ≤ 14 дней,
   ≤ 20 человек) → на каждого список занятых интервалов `{starts_at, ends_at, event_id?, kind}`:
   `kind = MEETING` — встречи Calab, где человек участник со статусом не «отклонил» (или организатор),
   развёрнутые вхождения; `event_id` отдаётся, только если спрашивающий видит эту встречу (§2 ADR-0038),
   иначе интервал без названия; `kind = EXTERNAL` — занятость из подключённого CalDAV (п. 4), всегда без
   названия; `kind = OFF_HOURS` не отдаём — рабочие часы приходят отдельно. Плюс на каждого `timezone` и
   `work_hours {start_min, end_min, days[]}` (новые поля `users.work_hours` — по умолчанию 10:00–19:00,
   пн–пт, в зоне пользователя; правятся в «Настройки → Календарь»). Гости и боты — 403; спрашивать можно
   только про участников пространства. Кэш не нужен: запрос по индексу `event_attendees(user_id)`.
2. **Подбор времени (сервер).** `POST /api/workspaces/{id}/freebusy/suggest {users[], duration_min,
   from, to, within_work_hours=true, room_id?}` → до 10 ближайших окон, где все свободны (и комната не
   занята другой встречей, если `room_id`), с шагом 15 мин; при `within_work_hours` — пересечение рабочих
   часов всех участников, если пересечение пустое — `409 NO_COMMON_HOURS` с подсказкой выключить флаг.
   Считается на сервере из тех же данных, что п. 1 (одна функция, юнит-тесты на стыки, DST и «весь день»).
3. **Клиент.**
   - **Иконка календаря** открывает **сегодняшний дневной вид сразу** (и раскрывает мини-календарь);
     повторный клик — закрывает. Мини-календарь остаётся для выбора дня.
   - **Фильтр «Люди»** над сеткой дневного вида: строка аватаров-чипов (пикер участников, поиск, ≤ 20,
     «Только мои» по умолчанию выключен) — сетка показывает встречи выбранных (объединение), у чужих
     встреч, которые смотрящий не видит, — серый блок «Занято». Выбор хранится в сторе на пространство и
     в URL-состоянии дня; сброс кнопкой «×».
   - **Режим «Подобрать время»** (кнопка в дневном виде и в диалоге встречи рядом с временем): те же
     чипы людей + длительность (30/45/60/90/кастом) + «в рабочие часы»; сетка дня показывает колонки
     занятости каждого (цвет по человеку, как в Календаре Apple «Доступность»), свободные общие окна
     подсвечены зелёным, серым — вне рабочих часов; список «Ближайшие окна» справа (из п. 2), клик по
     окну или по зелёной зоне → диалог встречи с заполненными временем и участниками; ←/→ по дням и
     «Следующее окно». В диалоге встречи под временем — полоска занятости выбранных участников и
     предупреждение «У Анны в это время встреча» (из п. 1), не блокирующее.
   - Мобильный веб: фильтр — шторка с чипами; подбор — список ближайших окон без сетки.
4. **CalDAV у пользователя (Настройки → Календарь → «Внешний календарь»).** Один аккаунт на пользователя:
   `caldav_accounts (user_id PK, url, username, secret_enc, calendar_href, push bool, import bool,
   last_sync_at, last_error, created_at)`. Пароль (app-specific password iCloud/Yandex/Fastmail/Nextcloud;
   Google CalDAV требует OAuth — не в v1, у Google остаётся `.ics` письмом) шифруется AES-GCM ключом,
   выведенным из серверного секрета (как `replay_seal`, ADR sessions), в API не возвращается. Подключение:
   `POST /api/me/caldav {url, username, password}` → сервер делает discovery (`PROPFIND`
   current-user-principal → calendar-home-set → список календарей) и отдаёт список для выбора; `PUT
   /api/me/caldav {calendar_href, import, push}`; `DELETE`; `POST /api/me/caldav/sync` (ручной, лимит
   раз в минуту). SSRF: только `https`, адрес проверяется той же политикой, что unfurl (`AllowAddr`),
   таймаут 10 с, ответ ≤ 2 МБ, редиректы не следуем.
   - **Импорт занятости** (`import`): раз в 15 мин (метёлка, распределённая блокировка) `REPORT
     calendar-query` на окно −1…+30 дней, из `VEVENT` берём только `DTSTART/DTEND/RRULE/STATUS/TRANSP`
     (TRANSP:TRANSPARENT и CANCELLED пропускаем) → `external_busy (user_id, uid, starts_at, ends_at)`;
     названия не храним. Занятость видна в п. 1 как `EXTERNAL`, в своём дневном виде — серые блоки
     «Занято · внешний календарь». Ошибка синка — в `last_error`, пользователю плашка в настройках.
   - **Экспорт встреч** (`push`): при создании/изменении/отмене встречи, где пользователь участник со
     статусом не «отклонил», сервер кладёт `PUT <calendar_href>/<event_id>.ics` (тот же `.ics`, что в
     письме; отмена — `DELETE`; повтор — RRULE серии) через очередь outbox-типа (повтор с backoff, ≤ 5
     попыток), чтобы не задерживать ответ API. Ответы участника из внешнего календаря не читаем.
5. **Права и лимиты.** Свободно/занято раскрывает только факт занятости; названия — по правилам
   видимости встреч. Рабочие часы и внешняя занятость — только участникам того же пространства. Лимиты:
   freebusy 60/мин на пользователя, suggest 30/мин, CalDAV-подключение 5/ч.

## Последствия
- Миграция (`users.work_hours`, `caldav_accounts`, `external_busy`, индекс `event_attendees(user_id)`),
  proto (`FreeBusy*`, `SuggestSlots*`, `CalDav*`, `UserSettings.work_hours`), сервер `internal/calendar`
  (+ `internal/caldav` — клиент, discovery, синк, push-очередь), клиент (фильтр, режим подбора, полоска в
  диалоге, настройки «Календарь»), docs/04, 05, 08, 16, 19, 20, TESTING C.22+, docs/09 #134.
- Не в v1: Google CalDAV (OAuth), чтение ответов из внешнего календаря, несколько аккаунтов CalDAV,
  экспорт в CalDAV встреч без участия пользователя, недельный вид подбора.
