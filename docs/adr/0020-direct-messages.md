# ADR-0020: Личные сообщения (DM) (2026-09-26)

## Контекст
Владелец: «нет возможности писать PM». Сейчас все сообщения живут в комнатах пространства (`rooms.workspace_id NOT NULL`), права считаются из ролей пространства. DM в Discord — глобальные, вне серверов.

## Решение
1. **DM — это комната без пространства.** `rooms.workspace_id` становится `NULL`-able, добавляется `type = 'dm'` и таблица `dm_members (room_id, user_id)` (ровно два участника) с уникальным ключом пары (`dm_key = least(a,b)||':'||greatest(a,b)`). Сообщения, файлы, реакции, unfurl, закрепы, read-state — те же таблицы и тот же код, что и для комнат.
2. **Права.** Для `dm` `computePermissions` (Go и TS, общие тест-векторы) возвращает фиксированный набор для обоих участников: VIEW_ROOM, READ_HISTORY, SEND_MESSAGES, ATTACH_FILES, ADD_REACTIONS, MANAGE_OWN_MESSAGES, PIN_MESSAGES; никаких ролей, MENTION_EVERYONE и модерации. Голос в DM — не сейчас (v2, ADR отдельно).
3. **Кому можно писать.** Пользователю, с которым есть общее пространство, либо уже существующий DM. Гости (ADR-0016) DM не видят. Блокировки — v2.
4. **API.** `POST /api/dms {user_id}` → get-or-create, 200/201 `{room, peer}`; `GET /api/dms` → список с `peer`, `last_message_at`, read-state. Сообщения — существующие `/api/rooms/{id}/messages*` (проверка доступа по `dm_members`).
5. **Gateway.** События DM-комнаты рассылаются по `user:<id>` обоим участникам (не по `ws:<id>`). `READY.dms[]` = `{room, peer(User), read_state}`. Новый DM у получателя появляется по `DM_CREATE`. Уведомление о DM — как об упоминании (всегда, с учётом «не беспокоить» и mute DM).
6. **Клиент.** В рейле сверху — «Личные» (иконка Calab/Home, как Discord Home) со счётчиком непрочитанных; список DM (аватар, имя, presence, последнее сообщение), чат переиспользует ленту/композер комнаты; «Написать» — из профиля и контекстного меню участника; поиск пользователя по общим пространствам (`GET /api/dms/candidates?q=`).

## Последствия
- Миграция 00011: `workspace_id` nullable + CHECK (`type='dm'` ⇔ `workspace_id IS NULL`), `dm_members`, индексы; все запросы по комнатам с `workspace_id` получают `WHERE` по типу.
- Presence/unread по DM — в READY и в существующих счётчиках без новых механизмов.
