# ADR-0057: Встроенный Calab Stikers (2026-10-02)

## Требование владельца
Встроенный во все клиенты стикерпак «Calab Stikers» с популярными эмоциями,
в стиле стикеров лендинга. Отдельный PR, без выпуска/деплоя.

## Решение лида и границы
- 16 статичных прозрачных WebP до 512×512 и 512 КБ каждый. Название сохраняет
  написание владельца. По одному emoji на стикер; поиск/недавние/ответы/реакции
  используют существующие механизмы ADR-0030. Анимация вне объёма.
- Глобальный неизменяемый пак: `sticker_packs.workspace_id = NULL`,
  `stickers.file_id = NULL` допустимы только для фиксированного набора ID,
  внесённых миграцией. Нет фиктивного пространства, пользователя и файлов в S3.
  Строки стикеров сохраняют FK сообщений и обычную историю/пересылку.
- Манифест и изображения поставляются с сервером через go:embed и с клиентами
  через сборку Vite из тех же исходников. Протокол StickerPack получает
  additive `builtin` flag. Сервер возвращает встроенный пак первым в installed
  всем авторизованным пользователям. Он не расходует квоты и 50 установок.
- Встроенный пак закреплён: нельзя удалить, изменить или переставить; UI показывает
  «Встроенный». CRUD не допускает глобальные паки. Порядок пользовательских паков
  обрабатывается отдельно. Никакой установки в каждой учётной записи.
- Отправка требует прежних прав комнаты SEND_MESSAGES и отсутствия блокировок;
  доступен всем тарифам и гостям (уточнение владельца 2026-10-02). В DM действуют существующие проверки
  доступа/гостей/блокировок DM. Общего пространства для глобального пака не нужно.
  Обычные паки сохраняют все ограничения ADR-0030.
- GET /api/stickers/builtin/{id}.webp возвращает только allowlist встроенных
  ресурсов, image/webp + nosniff + immutable cache. Эти брендовые изображения
  публичны, пользовательские файлы через этот путь недоступны.
- Клиент заменяет URL только при точном совпадении ID и pack_id с локальным
  манифестом. Неизвестные стикеры загружает с сервера обычным способом.
  Старый сервер не объявляет пак: новый клиент не предлагает неотправляемые ID.
  Старый клиент получает полноценные изображения сервера, но не знает новый UI-флаг.
- Обновления только append-only: ID/байты опубликованного стикера не заменяем;
  это сохраняет историю и immutable cache. Миграция Down блокируется, если
  встроенные стикеры уже используются сообщениями (не удаляет историю молча).

## Приёмка
- Встроенный пак виден без установки; обычные установки/порядок не меняются.
- Отправка, чтение истории, пересылка и emoji-поиск работают; сервер отклоняет
  отсутствие SEND_MESSAGES и попытки изменить пак/его изображения; гости отправляют и пересылают пак.
- Free-квоты не меняются. Ресурсы существуют, прозрачны, проходят WebP-валидатор.
- Целевые unit/integration и typecheck/lint; QA затронутого пикера.
- Независимые security/protocol reviews обязательны перед merge. Владелец запретил
  субагентов; PR отмечает этот незавершённый gate, не подменяет его самопроверкой.

## Совместимость с identity
Публичные байты включены в route census как public. Чтение метаданных только
фиксированного built-in ID использует aggregate policy (как список паков),
поэтому workspace_sso видит пак без глобальной authority; recovery остаётся
запрещён. Отправка по-прежнему проверяет identity scope целевой комнаты и
mutation guard. Тест проверяет разрешённую A и запрещённую B scoped-сессии.
