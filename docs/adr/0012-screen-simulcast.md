# ADR-0012: Стрим экрана — AV1 simulcast вместо SVC; кодирование программное (hw только где есть) (2026-09-25)

Уточняет ADR-0005 по результатам медиа-спайка (docs/02, раздел «Результаты спайка»).

## Контекст
- livekit-client 2.22 для screen share с AV1/VP9 без simulcast всегда выставляет `L1T3` и переписывает `contentHint` на `motion` — выбор `L2T3_KEY`/`L3T3_KEY` не действует. С одним слоем превью 320×180 получает полный поток 1080p15 (~760 kbps статика, ~2 Mbps скролл): SFU не снижает fps для превью.
- В режиме AV1 **simulcast** (livekit-server ≥ 1.13.7) SDK сохраняет `contentHint: detail`, каждый слой кодируется как `L1T3`; превью получает 640×360 (8 kbps статика / ~250 kbps скролл), верхний слой не кодируется, пока никто не смотрит (dynacast).
- В Electron 44 на macOS (M4) все кодеки — AV1, VP9, H.264 (OpenH264) — кодируются программно; OpenH264 на `original` дороже AV1 (109 % против ~55 % ядра). Декодирование AV1 — аппаратное.

## Решение
- Стрим экрана публикуется как **AV1 + simulcast**, `contentHint: detail` (переключатель `motion`), пресеты и потолки из ADR-0005 без изменений.
- На macOS аппаратного кодирования в Electron нет ни для одного кодека → AV1 всегда. На **Windows** Chromium использует hw H.264 (Media Foundation: Intel QSV / NVENC / AMD) и на новых GPU hw AV1 — это надо подтвердить замером на Windows-машине (`encoderImplementation` в панели статистики, чек-лист в TESTING.md). Если hw доступен, клиент предпочитает hw-кодек для пресета `original`; для 720p/1080p15 — AV1 (лучшее сжатие текста, CPU 30–70 % одного ядра).
- Автопонижение: при `qualityLimitationReason: cpu` клиент сам опускает пресет (original → 1080p → 720p) и показывает подсказку. Дефолт 1080p15 — не 30 fps.
- Linux: только программное кодирование (VA-API в Chromium выключен) → AV1.
- Системный звук при стриме на macOS выключен по умолчанию: `restrictOwnAudio` не исключает звук нашего процесса (замер −11.7 dBFS утечки) — голоса участников ушли бы обратно в комнату. Включение — с предупреждением.
- Библиотека шумоподавления — `@timephy/rnnoise-wasm` (отдаёт вероятность речи → VAD).

## Последствия
- Замеры на M4 (AV1, detail): 1080p Retina-экран — 228 kbps, 32 % ядра; `original` (2940×1912) — 660–815 kbps, 72–80 % ядра; статичный текст 18–37 kbps на всех пресетах. Требования по трафику для роуминга выполнены.
- Пересмотреть, если libwebrtc/LiveKit начнут применять SVC-режимы для screen share или появится аппаратный AV1-энкодер в Chromium на macOS/Windows.
