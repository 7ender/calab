# ADR-0033: Пересылка сообщений (в том числе карточки записи встречи) (2026-09-28)

## Контекст
Владелец: «сделать возможность переслать транскрибацию кому-то». Карточка записи (ADR-0025) —
системное сообщение комнаты, где шла встреча: самари, транскрипт (`GET …/recordings/{rid}/transcript`,
VIEW_ROOM в этой комнате) и аудио (вложение сообщения) видны только тем, кто видит эту комнату. Общей
пересылки сообщений в Calab нет (docs/09 #38 — «Переслать (позже)»); самари можно скопировать
(docs/09 #80), но аудио и транскрипт так не передать. Telegram/Discord пересылают любое сообщение
как копию с пометкой «Переслано от». Нужен один механизм и для текста, и для карточки.

## Решение
1. **Пересылка = новое сообщение-копия в целевой комнате** от имени пересылающего с ссылкой на
   оригинал. Proto: `Message.forward` (`Forward {author_id, room_id, message_id, sent_at}`,
   `room_id` пустой для DM-источника вне пространства получателя не скрывается — комната просто
   может быть недоступна читателю; клиент показывает только имя автора и дату). БД: столбцы
   `messages.forwarded_from uuid REFERENCES messages(id) ON DELETE SET NULL` (**всегда id
   первоисточника**: пересылка пересланного ссылается на оригинал, один уровень) и
   `messages.forward_author_id uuid REFERENCES users(id)` + `forward_sent_at timestamptz`
   (чтобы пометка жила и после удаления оригинала); индекс по `forwarded_from`. Миграция 00034.
2. **API.** `POST /api/rooms/{id}/messages/{mid}/forward {to_room_id}` → 201 `{message}`
   (новое сообщение целевой комнаты). Права: в источнике — как на чтение сообщения (VIEW_ROOM,
   `messages.deleted_at IS NULL`); в цели — как на отправку (`SEND_MESSAGES`, DM — участник пары и
   правило «можно писать» ADR-0020/#canDm, для гостей — их обычные права). Комната-источник
   «только по списку» (ADR-0029) **не запрещает** пересылку: это осознанное действие участника с
   доступом, как копирование текста; клиент показывает в диалоге пометку «Комната только по
   списку — получатель увидит содержимое». Пересылка между пространствами разрешена (у
   пользователя есть доступ к обоим). Нельзя переслать: удалённое, команду боту (`MessageCommand`
   не копируется), сообщение из комнаты, где `deleted_at` у записи (см. п. 4 — карточка
   «Запись удалена» пересылается как есть, но не даёт ничего). Один запрос — одна цель; клиент
   для нескольких целей шлёт несколько запросов последовательно. Лимит: обычный rate limit
   отправки сообщений.
3. **Что копируется.** `content`, `sticker`, `embeds_hidden`; вложения — новые строки
   `message_attachments` на **те же** `files` (без копирования блоба и без учёта в квоте
   получателя: файл уже посчитан загрузившему). Доступ на чтение файла уже считается «VIEW_ROOM
   в любой живой комнате, где сообщение с этим файлом» (`files.CanRead`/`FileRooms`) — копия
   даёт доступ читателям целевой комнаты автоматически; удаление копии его отзывает. Не
   копируются: реакции, закреп, `reply_to` (ответ становится обычным текстом), `nonce`, упоминания
   (в копии `@` не уведомляют — `mentions` для пересланного не создаются, чтобы не дёргать людей
   чужим текстом), `command`. Превью ссылок (unfurl) для копии строится заново по контенту.
4. **Карточка записи.** Копия — тоже `kind = SYSTEM` с тем же `SystemMessage.recording`
   (тот же `recording_id`) и `forward`. Карточка обновляется на месте по ходу обработки
   (`System.Update`) — обновление и `deleted_at` **рассылаются во все копии**: `System.Update`
   помимо `message_id` записи обновляет сообщения с `forwarded_from = message_id` (MESSAGE_UPDATE
   в каждую комнату). Транскрипт: `GET /api/rooms/{id}/recordings/{rid}/transcript` принимает
   как комнату записи, так и комнату, где есть живое (не удалённое) сообщение с
   `forwarded_from` = сообщение-карточка этой записи (запрос `RecordingVisibleInRoom`); права —
   VIEW_ROOM в `{id}`. Аудио — вложение, пересылается по п. 3 (пока `audio_until` не истёк;
   после — копия без аудио, как оригинал). Удалить запись, «Проверить снова»/«Отправить снова» —
   только из комнаты записи (`room_recordings.room_id`); в копии этих пунктов нет, есть
   «Переслать» и «Копировать самари». Пересылка карточки в состояниях RECORDING/UPLOADING/
   PROCESSING разрешена — копия догонит через п. 4.
5. **Клиент.** «Переслать» в контекстном меню сообщения (docs/09 #38, между «Копировать текст»
   и «Закрепить») и в меню «⋯» карточки записи. Диалог «Переслать…» (kind `forward`): одно
   поле поиска, список — «Личные» (люди, с которыми можно писать — как в `NewDmDialog`) и
   комнаты текущего пространства с правом отправки, мультивыбор чипами (как в TG), кнопка
   «Переслать» → запросы по очереди, тост «Переслано в N чатов» / ошибка по цели. В ленте:
   строка «↪ Переслано от <имя> · <дата>» над содержимым в стиле цитаты ответа (тонкая, `text-caption
   text-muted`, иконка `Forward`), имя — по `forward.author_id` (`useMemberName`, иначе «участник»);
   дата — время пересылки (`created_at` копии); дата оригинала (`forward.sent_at`) — в подсказке.
   Карточка записи с пометкой — та же карточка, без кнопок удаления/повтора. Пересланное
   сообщение редактировать нельзя (422 `MESSAGE_NOT_EDITABLE`), удалять — как своё.
6. **Боты (ADR-0031).** Маршрут в таблице `botAllow`; бот получает `forward` в MESSAGE_CREATE.
   Bot SDK — метод `forward(roomId, messageId, toRoomId)`, docs/19.
7. **Поиск/уведомления.** Копия индексируется как обычное сообщение; уведомление получателю — как
   о новом сообщении (DM — всегда, комната — по настройкам), без упоминаний из текста (п. 3).

## Последствия
- Изменение протокола и путей прав (чтение файла через копию, транскрипт через копию, отправка
  в DM) — **второе security-ревью обязательно** (CLAUDE.md п. 5). Интеграционные тесты: пересылка
  в DM и в другую комнату (в т. ч. другого пространства); получатель читает аудио и транскрипт
  через копию; после удаления копии доступа нет; удаление записи гасит копии; в комнату без
  SEND_MESSAGES — 403; удалённое/командное — 404/422; из restricted-комнаты — 201.
- docs/04 «Сообщения» и «Запись встреч», docs/05 (MESSAGE_UPDATE на копии), docs/08 «Лента»
  (пометка «Переслано от»), docs/16 (строка про forward), docs/19 (SDK).
- Старые клиенты (≤ 0.7.3) показывают копию как обычное сообщение без пометки — допустимо.

## Пометка по реализации (2026-09-28)
- В `message_attachments` был уникальный индекс «один файл — одно сообщение» (защита от прикрепления чужой загрузки ко второму сообщению). Для копий добавлен столбец `message_attachments.forwarded`; уникальность действует только по непересланным строкам, для копий — обычный индекс по `file_id`. Аудио записи, появившееся после пересылки карточки, прикрепляется и к её копиям.
- Ревью (без блокеров): копия показывает id автора и комнаты-источника всем читателям — принято как сознательное действие пересылающего; копия карточки сохраняет доступ к транскрипту после потери доступа к исходной комнате — по замыслу (как пересланный файл). Минорные замечания — docs/12.
