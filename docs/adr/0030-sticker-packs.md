# ADR-0030: Стикерпаки пространства (2026-09-27)

## Контекст
Владелец (docs/09 #58): стикерпаки как в Telegram — WebP (статичные и анимированные), паки создаются в пространстве, пользователь «устанавливает» паки себе, стикер — отдельное сообщение без фона. Нужно не сломать права (ADR-0008/0026), тарифы (ADR-0024), бюджет CPU ленты (docs/14) и безопасность файлов (docs/04 «Файлы»).

## Решение
1. **Модель** (миграция 00028). `sticker_packs(id, workspace_id → CASCADE, name 1..64, short_name [a-z0-9_]{1,32} UNIQUE в пространстве среди живых, cover_sticker_id?, created_by, created_at, updated_at, deleted_at?)`; `stickers(id, pack_id → CASCADE, file_id → files CASCADE, emoji (одна эмодзи-последовательность), position, width, height, animated, created_at, deleted_at?)`; `user_sticker_packs(user_id, pack_id, position, added_at)` PK `(user_id, pack_id)`; `messages += sticker_id? → stickers ON DELETE SET NULL`. Байты стикера — обычная строка `files` пространства (ключ `<workspace>/<file_id>`, `image/webp`, без превью), в квоте хранения. Чистка сирот пропускает файлы стикеров.
2. **Удаление** не ломает историю: стикер/пак, на который ссылаются сообщения, помечается `deleted_at` (из пикеров и списков исчезает, в ленте виден); стикер без ссылок удаляется сразу, его файл уходит обычной чисткой сирот (квота освобождается). Удаление пака снимает его у всех (`user_sticker_packs`).
3. **Права.** Новый бит `MANAGE_STICKERS = 1 << 16` (уровень пространства, как `MANAGE_ROLES`: в переопределениях комнат игнорируется, API — `422`), у owner/admin — через `ADMINISTRATOR`. Почему не `MANAGE_WORKSPACE`: тот даёт инвайты, исключения и баны; стикеры — контент, который владелец хочет доверить «дизайнеру» без модерации (как Discord `MANAGE_EMOJIS_AND_STICKERS`). Цена — правка `computePermissions` (Go+TS, векторы: `ALL` = 131071) и второе ревью. Не-админ выдаёт бит роли, только если держит его сам (общее правило `checkGrant`). Гости: `GuestMax` бит не содержит.
4. **Кто что может.** Смотреть паки пространства и стикеры в ленте — все участники (гости тоже). Устанавливать паки и отправлять стикеры — не-гости. Пак пространства W доступен: в комнатах W (нужен `SEND_MESSAGES`, не `ATTACH_FILES`) и в DM, если оба участника — не-гости W. Чтение файла стикера (`GET /api/files/{id}`) — участник W или стикер в живом сообщении комнаты, которую видит вызывающий.
5. **Контракт** (`sticker.proto`). `Sticker {id, pack_id, emoji, url, width, height, animated, size}`, `StickerPack {id, workspace_id, name, short_name, cover_sticker_id, stickers[], …}`; `Message.sticker` (сообщение-стикер: пустой `content`, без вложений, правка запрещена), `CreateMessageRequest.sticker_id`, `DmLastMessage.sticker_emoji`. REST: `GET/POST /api/workspaces/{id}/sticker-packs`, `PATCH/DELETE /api/sticker-packs/{id}`, `POST /api/sticker-packs/{id}/stickers` (multipart партией: поле `emoji` перед каждым `file`, ≤ 50 за раз, всё или ничего), `PATCH/DELETE /api/stickers/{id}`; `GET /api/me/sticker-packs` (`installed` по порядку + `available` из моих пространств), `PUT/DELETE /api/me/sticker-packs/{id}`, `PUT /api/me/sticker-packs/order`. События `STICKER_PACK_CREATE|UPDATE|DELETE` (пак целиком) — всем участникам пространства; установка/порядок — без события (клиент перечитывает список).
6. **Лимиты.** Файл: ≤ 512 КБ статичный, ≤ 1 МБ анимированный; стороны 1..512; анимация ≤ 300 кадров и ≤ 10 с; ≤ 120 стикеров в паке; ≤ 50 установленных паков у пользователя. Тариф (ADR-0024, `PLAN_FREE_LIMITS`/`PLAN_TEAM_LIMITS`): `sticker_packs` (free 5) и `stickers` (free 200, на пространство); упор → `409 CONFLICT, reason PLAN_LIMIT, used/limit`. Team — без лимита.
7. **Валидация WebP на сервере** (свой парсер, без декодера): `RIFF` + размер = длине файла (± паддинг) + `WEBP`; чанки только `VP8 `, `VP8L`, `VP8X`, `ALPH`, `ANIM`, `ANMF`, `ICCP`, `EXIF`, `XMP `; длины в пределах файла; размеры из `VP8 ` (стартовый код `9d 01 2a`), `VP8L` (сигнатура `0x2f`) или `VP8X` (canvas); анимация = флаг `VP8X` + `ANIM` + ≥ 1 `ANMF`, кадры внутри canvas. Иначе `422`. Отдаётся `image/webp`, `nosniff`, `CSP: sandbox`, `inline` (как картинки).
8. **Производительность.** Стикер — `<img>` (декодирует браузер) 160×160, без фона. Анимированный играет, только если виден (`IntersectionObserver`), окно не скрыто, нет `prefers-reduced-motion`/«слабого компьютера» и играющих < 6 (очередь по видимости); иначе вместо `<img>` — статичный первый кадр (`createImageBitmap` → `<canvas>`, один раз на стикер). Пикер рендерит только видимую сетку текущего пака.
9. **UI.** Вкладка «Стикеры» в панели эмодзи (недавние, паки по порядку, поиск по эмодзи; `:`-автодополнение не трогаем), мобильный веб — та же шторка; «Добавить пак» по клику на чужой стикер; «Настройки пространства → Стикеры» (`MANAGE_STICKERS`); «Профиль → Мои стикеры» (порядок, удалить). Превью/уведомления — «🧩 Стикер» (или его эмодзи).

## Последствия
- Новый бит прав → второе ревью (security), векторы `proto/testdata/permissions.json`, docs/16.
- Удалённые стикеры с сообщениями держат файл, пока живы сообщения; сборка «удалить по последней ссылке» — docs/12.
- Реакции-стикеры, стикеры в статусе, TGS/WebM — вне объёма.
