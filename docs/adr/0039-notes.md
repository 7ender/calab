# ADR-0039: «Заметки» — личные полки сообщений (2026-09-29)

## Контекст
Владелец (docs/09 #117): «над DM такую штуку как Notes: условные комнаты, куда можно закидывать
сообщения, как Saved Messages, и форвардить туда и оттуда». Нужны несколько именованных «полок»
только для себя: текст, файлы, голосовые, закрепы, реакции, поиск — та же лента, что у комнат и DM;
пересылка (ADR-0033) — в обе стороны. Квота файлов сейчас есть только у пространств (ADR-0024).

## Решение
1. **Полка — комната без пространства.** `rooms.type = 'notes'`, `workspace_id NULL`, `dm_key NULL`;
   имя (≤ 40 символов) — `rooms.name`, порядок — `rooms.position`, эмодзи — новый столбец
   `rooms.emoji` (`''` = без эмодзи, только у полок). CHECK: `type IN ('dm','notes')` ⇔
   `workspace_id IS NULL`. Миграция 00043.
2. **Владелец — единственная строка в `dm_members`** (а не новый столбец `rooms.notes_owner_id`).
   Почему: доступ к DM уже целиком построен на `dm_members` — `GetRoomAccess` отдаёт участников,
   `perm.Resolver` даёт фиксированный набор DM, `rooms.Publish` рассылает события по `user:<id>`
   участникам, загрузка файлов (`POST /api/dms/{id}/files`), скачивание, закрепы, реакции,
   read-state, поиск в комнате, пересылка (`acc.DM`) — всё работает без веток. Столбец владельца
   потребовал бы второй ветки в `GetRoomAccess`, резолвере и каждом месте с `acc.DM`. Отличия полки
   от DM — узкие и явные: `RoomAccess.Notes` (нет звонков/голоса/стрима/камеры/саундборда: 404),
   `ListDMs`/`GetDMPeer` полку не находят (нет второй строки — нет собеседника), источник
   пересылки из полки не раскрывается (`Forward.room_id` пустой, как у DM).
3. **Права.** `computePermissions` не меняется: полка получает набор DM (VIEW_ROOM, SEND_MESSAGES,
   ATTACH_FILES; закреп — по типу комнаты, как в DM). Кроме владельца полку не видит никто —
   чужой id → 404. Боты и гостевые аккаунты — 403 на `/api/notes*` (и полок у них нет в READY).
4. **Лимит — 20 полок на пользователя** (создание под advisory-lock пользователя; 21-я — 409 `CONFLICT`
   с `reason = "NOTES_LIMIT"`, `used/limit`). Удаление полки — жёсткое: `DELETE rooms` каскадом удаляет сообщения,
   реакции, закрепы, read-state; вложения становятся сиротами и уходят обычной очисткой файлов
   (копии, пересланные в другие чаты, остаются — это их вложения).
5. **Личная квота.** `users.storage_quota_bytes bigint NULL` (NULL = `DEFAULT_PERSONAL_QUOTA_BYTES`,
   по умолчанию 1 GiB); меняет суперадмин: `PUT /api/admin/users/{id}/storage-quota`. В квоту
   входят файлы пользователя вне пространств, лежащие в его полках, и ещё не прикреплённые
   загрузки. Проверка — в `POST /api/dms/{id}/files` для полки, под тем же lock, что и общий лимит
   хранилища; превышение — 413 `FILE_QUOTA_EXCEEDED` с
   `reason = "PERSONAL_QUOTA"`, `used/limit` в байтах. Пересылка в полку квоту не тратит (те же
   файлы, ADR-0033 §3). Загрузки в DM, как и раньше, личной квотой не ограничены (строка в
   docs/12).
6. **API.** `GET /api/notes` (полки по position), `POST /api/notes {name, emoji}` → 201,
   `PATCH /api/notes/{id} {name?, emoji?, position?}`, `DELETE /api/notes/{id}` → 204.
   Сообщения — существующие `/api/rooms/{id}/messages*`, файлы — `POST /api/dms/{id}/files`.
7. **Gateway/proto.** `RoomType.NOTES`; `NotesShelf {room, emoji, last_message}`;
   `Ready.notes[]`; события `NOTES_CREATE / NOTES_UPDATE / NOTES_DELETE` по `user:<id>` на все
   устройства владельца; `MESSAGE_*` полки идут туда же (пустой `workspace_id`), как у DM.
8. **Клиент.** В колонке «Личные» над списком DM — раздел «Заметки»: строки полок (эмодзи, имя,
   последнее сообщение), «+ Полка» (имя + эмодзи прямо в строке), «⋯» — переименовать, сменить
   эмодзи, удалить с подтверждением. Полка открывается тем же `ChatPane` (без панели участников и
   голоса). «Переслать» показывает полки группой «Заметки»; ⌘K находит полки; мобильная шторка —
   тот же раздел.

## Последствия
- Каждое место с `acc.DM` работает для полки; места, где DM значит «двое» (звонки, typing,
  архив/очистка DM, уведомления о входящих), полку не видят: собеседника нет.
- Непрочитанных в полке не бывает (свои сообщения помечаются прочитанными при отправке).
- Удаление большой полки — один каскадный `DELETE`; при 20 полках на человека это приемлемо.
