# ADR-0016: Гостевой доступ в комнату по ссылке (2026-09-26)

## Контекст
Владелец хочет приглашать в конкретную комнату людей извне: по ссылке человек попадает сразу в комнату; если у него нет доступа к workspace — видит только эту комнату; если не зарегистрирован — вводит ник и входит без регистрации.

## Решение
- **Ссылка комнаты**: `room_invites (id, room_id, code, created_by, expires_at, max_uses, uses, allow_guests, revoked_at)`; URL `https://<domain>/r/<code>` (веб) и `calaba://r/<code>` (десктоп). Создаёт `MANAGE_ROOM` или `MANAGE_WORKSPACE`; можно отозвать.
- **Гостевой пользователь**: `users.is_guest = true`, без email/пароля, `display_name` = введённый ник, сессия TTL 24 ч (продлевается активностью), `guest_expires_at`; чистка неактивных гостей и их членств через 7 дней. Rate-limit создания гостей по IP.
- **Членство гостя**: `workspace_members` с ролью `guest` + `room_permissions` override для этого пользователя `allow: VIEW_ROOM | CONNECT | SPEAK | SEND_MESSAGES` (без ATTACH_FILES и STREAM по умолчанию; флаги в настройках ссылки). Роль `guest` по дефолту не видит ни одной комнаты (ADR-0008), поэтому гость видит ровно комнаты, куда приглашён.
- **Сценарии перехода по ссылке**: (a) залогинен и участник → сразу в комнату; (b) залогинен, не участник → становится `guest` этого workspace с override на комнату; (c) не залогинен → экран «Введите имя» → гостевой аккаунт → в комнату. В UI гость помечен бейджем «Гость»; админ может превратить гостя в участника (роль member) или удалить.
- **Ограничения**: гость не может создавать инвайты, менять профиль кроме имени, писать в другие комнаты; в списках участников виден только в приглашённых комнатах.

## Последствия
- Изменения схемы: `users.is_guest`, `users.guest_expires_at`, `room_invites`; `users.email` становится nullable.
- Веб-клиент — основной путь гостя (без установки); десктоп поддерживает ссылку через deep link.
- Безопасность: ссылка = capability; по умолчанию срок 7 дней, отзыв в настройках комнаты; аудит `uses`.
