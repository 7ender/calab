# ADR-0023: Почта — подтверждение email, приглашения по email, сброс пароля (2026-09-27)

## Контекст
Владелец: «поиск по email, чтобы добавить в пространство; если не найден — письмо-приглашение; валидация почты кодом». Сейчас регистрация без подтверждения, приглашения — только ссылкой/кодом. Есть почтовый сервер владельца (`mail.unne.ai`), SMTP выдаётся отдельно.

## Решение
1. **Транспорт.** Пакет `internal/mail`: SMTP из env (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `SMTP_TLS=starttls|tls|none`), outbox в Postgres (`mail_outbox`: to, template, params, locale, attempts, next_at, sent_at, error) с воркером и экспоненциальными ретраями (до 24 ч), лимиты: ≤ 3 письма на адрес в час, ≤ 200 в час на инстанс. В dev — Mailpit (`infra:dev`), в тестах — фейк. Шаблоны — текст + простой HTML, 4 локали по `users.locale`/языку клиента (`Accept-Language` при регистрации), тема и тело из словаря `internal/mail/i18n`.
2. **Подтверждение email.** `users.email_verified_at`; таблица `email_codes(user_id, purpose verify|change|reset, code_hash, expires_at, attempts, created_at)`: 6 цифр, 10 мин, 5 попыток, повторная отправка ≥ 60 с. `POST /api/auth/verify/send`, `POST /api/auth/verify {code}`, смена email — код на новый адрес. Неподтверждённый аккаунт: вход и чтение — можно; создание пространств, приглашения, DM инициировать — нельзя (403 `EMAIL_NOT_VERIFIED`); клиент показывает плашку «Подтвердите почту» с полем кода. Существующие пользователи — считаются подтверждёнными миграцией (grandfather), кроме тех, кого владелец решит перепроверить (флаг в админке — v2).
3. **Сброс пароля.** `POST /api/auth/password/forgot {email}` (всегда 204), письмо с кодом/ссылкой, `POST /api/auth/password/reset {code, password}`; отзыв всех сессий после сброса.
4. **Приглашение по email.** В диалоге «Пригласить»: `POST /api/workspaces/{id}/invites/lookup {email}` (право INVITE, точное совпадение email, ≤ 20 запросов/мин) → `{user}` (имя, аватар, уже участник?) или `{}`. Если найден — `POST /api/workspaces/{id}/members {user_id}` (сразу участник; событие + письмо «вас добавили в …»). Если нет — `POST /api/workspaces/{id}/invites/email {email, role?}`: запись `email_invites(workspace_id, email, invited_by, code, expires_at 7 д, accepted_at)`, письмо со ссылкой `https://app.calab.ru/join/<code>`; при регистрации с этим email (после подтверждения) — автоматическое вступление; повторное приглашение того же адреса — не чаще раза в сутки. Список/отзыв email-приглашений — в настройках пространства.
5. **Безопасность.** Коды хэшируются (bcrypt/argon2id), сравнение с ограничением попыток; `lookup` не раскрывает наличие аккаунта никому без права INVITE и логируется; письма не содержат паролей; ссылки одноразовые; все лимиты — в Valkey (существующий лимитер).

## Последствия
- Миграции 00015–00016 (outbox, codes, email_invites, `email_verified_at`).
- Онбординг получает шаг «Подтвердите почту» (после регистрации), вход — «Забыли пароль?».
- Клиент: диалог приглашения с поиском по email, плашка подтверждения, экран сброса; веб — те же экраны.
- Инфра: `SMTP_*` в `.env` стенда (только там), SPF/DKIM/DMARC для домена отправителя — на стороне владельца (`calab.ru` → `mail.unne.ai`).
