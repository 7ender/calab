# ADR-0025: Запись встреч и транскрибация через GPTunneL (2026-09-27)

## Контекст
Владелец: подключать пространство к GPTunneL по коду (как в `gptunnel-recorder`), любой участник (не гость) включает «Запись встречи» из меню комнаты, запись у всех видна, транскрипт уходит в GPTunneL. Исследование `gptunnel-recorder` (packages/recorder): pairing — код `ABCD-EFGH` → `POST /v1/meetings/device/pair` → device token (Bearer); загрузка готового файла `POST /v1/meetings/device/recordings` + `PUT …/data` кусками 8 МБ (`Content-Range`, возобновление) + `POST …/complete`; `GET …/recordings/:id` → `status`, `web_url`; принимаются только `audio/mpeg` и `video/mp4`; ≤ 4 ч, ≤ 4 ГБ; транскрипт/саммари доступны только веб-сессии GPTunneL (device token отдаёт лишь ссылку). Рекордер — не библиотека; контракт — простой HTTP.

## Решение
1. **Источник звука — сервер (LiveKit Egress, room composite, audio-only)**, не клиент инициатора: запись не зависит от его выхода/сети, права и индикация — на сервере, GPU не нужен (~1 CPU на запись). Выход — `MP4` (AAC, audio-only) → это `video/mp4`, ffmpeg не нужен. Контейнер `livekit/egress` в compose (тот же Valkey, API key LiveKit, общий volume `recordings_data`, лимит одновременных записей `RECORDING_MAX_CONCURRENT=3`).
2. **Подключение к GPTunneL** — в настройках пространства (владелец/MANAGE_WORKSPACE): поле кода из GPTunneL → сервер `POST /v1/meetings/device/pair {code, name: "Calab · <workspace>", platform: "calab", app_version}` → device token хранится **на сервере** у пространства (`workspace_integrations(kind='gptunnel', token_enc, device_name, paired_by, paired_at, revoked_at)`, шифрование как у outbox), «Отключить» → `DELETE /me` + пометка. Базовый URL — env `GPTUNNEL_API_URL` (по умолчанию `https://gptunnel.ru`; изменено 27.09, docs/09 #47: было `https://gptunnel.ai`); ссылки `web_url` с хостом `app.gptunnel.ai` показываются на `GPTUNNEL_WEB_URL` (`https://gptunnel.ru`).
3. **Запись**: `POST /api/rooms/{id}/recording/start|stop` (участник пространства, не гость; нужна подключённая интеграция, иначе 409 `NOT_PAIRED` с подсказкой владельцу); одна запись на комнату; сервер стартует egress, пишет `room_recordings(id, room_id, started_by, started_at, stopped_at, egress_id, file, status pending|recording|uploading|processing|done|failed, gptunnel_id, web_url, error)`, публикует `ROOM_RECORDING {room_id, state, by_user_id, since}` всем в пространстве; авто-стоп при пустой комнате (2 мин) и по лимиту 4 ч; при рестарте сервера — reconcile по списку egress.
4. **После стопа**: сервер загружает файл в GPTunneL (чанки, возобновление, ретраи через outbox-подобную очередь), опрашивает статус до `done|failed` (backoff, ≤ 2 ч), удаляет локальный файл после `done` (или через 7 дней), пишет в чат комнаты системное сообщение «Встреча записана · N мин · Открыть в GPTunneL» (карточка с `web_url`; `failed` — с причиной, включая `insufficient_balance`). Транскрипт/саммари в чате — v2 (27.09, docs/09 #47, docs/17): после `done` файл не удаляется, а становится аудио-вложением карточки (`audio/mp4`, квота пространства, `RECORDING_KEEP_DAYS`, по умолчанию 30), сервер забирает `GET …/recordings/:id/result` (саммари) и `GET …/transcript` (постранично) и хранит у себя (`room_recordings.summary`, `transcript_json`, миграция 00026); нет методов у GPTunneL (404) — повтор ≈ 3,5 суток, потом карточка только со ссылкой. Удаление записи из карточки (docs/09 #50) — `DELETE /api/rooms/{id}/recordings/{rid}` и `DELETE` в GPTunneL.
5. **Индикация**: у всех участников — красная точка + «REC» + таймер на строке/карточке комнаты, пилюля в панели «Голос подключён», в мобильной полосе; при входе в комнату с записью — тост «Идёт запись встречи»; звук старта/стопа записи (тумблер).
6. **Приватность/права**: гости не могут включать; владелец пространства может запретить записи в настройках комнаты (`allow_recording`, по умолчанию да); всё логируется в `room_recordings`.

## Последствия
- Инфра: сервис `egress` в compose (стенд: CPU есть), volume, env `GPTUNNEL_API_URL`, `RECORDING_MAX_CONCURRENT`, лимит диска; бэкапы не включают записи (временные).
- Миграция 00019 (`workspace_integrations`, `room_recordings`); proto: `RoomRecording`, событие `ROOM_RECORDING`, поля в READY (текущие записи).
- Клиент: вкладка «GPTunneL» в настройках пространства (код, статус, отключить), пункт «Запись встречи / Остановить запись» в меню «…» комнаты, индикация, системная карточка в чате.
- Просьба к GPTunneL (владелец): эндпоинт результата для device token, приём `audio/ogg`, подсказка имён спикеров.
