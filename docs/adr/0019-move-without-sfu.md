# ADR-0019: Перемещение участника между комнатами без SFU-move (2026-09-26)

## Контекст
`MoveParticipant` в LiveKit OSS v1.13 отвечает `not implemented` — это возможность только LiveKit Cloud. Наш `POST /api/rooms/{id}/voice/{userId}/move` (P0.5, drag&drop участников) на self-hosted стенде всегда возвращал 503; интеграционные тесты подменяли вызов фейком и не поймали это.

## Решение
Перемещение реализуется на уровне приложения:
1. Сервер проверяет права и лимиты как раньше, записывает voice-state в целевую комнату, выпускает **join-токен целевой комнаты** для перемещаемого и публикует ему `VOICE_MOVED {from, to, by_user_id, url, token}`; всем остальным — `VOICE_STATE_UPDATE`.
2. Клиент по `VOICE_MOVED` немедленно отключается от старой комнаты и подключается к целевой с полученным токеном (короткий разрыв ~1 с, микрофон/стрим восстанавливаются по прежним настройкам; стрим — заново по запросу).
3. Через 5 с сервер удаляет участника из старой комнаты (`RemoveParticipant`), если он ещё там; при неудачном подключении к целевой voice-state откатывается по webhook.
4. Если LiveKit поддерживает `MoveParticipant` (Cloud), используется он — без разрыва; выбор — по ответу `not implemented` (кэшируется на процесс).

## Последствия
- Небольшой разрыв звука при перемещении на OSS; UX сохраняется (тост «Вас переместили в …»).
- Тесты перемещения — только против реального LiveKit, без фейков.
