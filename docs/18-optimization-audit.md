# 18. Аудит оптимизаций (27.09.2026)

Только исследование, продуктовый код не менялся. Цель владельца: найти, что ускорить, ничего не сломав.
База: main `86c54e4`, MacBook Air M4. Замеры CPU и таймеров уже есть в docs/14-energy.md, здесь они не повторяются.

## 10 безопасных первых шагов

Итог по шагам 1–10 (ветка оптимизаций): perf-probe на финальной сборке — рендеры на 20 сообщений 84,6 → 36,5 тыс., на 21 переключение 145 → 54 тыс., heap после 105 переключений 16,0 → 14,9 МБ, REST за 105 переключений 156 → 56.

1. **Минифицировать renderer.** electron-vite 5 по умолчанию собирает renderer без минификации. Главный чанк весит 4,34 МБ, после esbuild `--minify` 2,29 МБ (−47 %). Компиляция V8 на M4 117 → 82 мс. Добавить `sourcemap: 'hidden'`, чтобы логи можно было расшифровать. ✅ **Сделано:** главный чанк 4 338 → 2 145 КБ, `out/renderer` без карт 7,2 → 4,9 МБ, компиляция модуля V8 (M4, та же сессия) 35 → 26 мс. Карты `hidden` лежат в `out/`, в пакет не идут; для perf-probe сборка с `CALABA_RENDERER_MINIFY=0` (имена компонентов).
2. **`electronLanguages: [ru, en, es, zh_CN, zh_TW]` в electron-builder.** Сейчас в бандле 220 `locale.pak` Chromium: 50,4 МБ на диске, 13,0 МБ в сжатом виде. После фильтра каждый dmg/zip станет меньше на ≈ 11,5 МБ (−9 %). ✅ **Сделано:** в списке оба написания (`en`/`en-US`, `zh_CN`/`zh-CN`, `es_419`/`es-419`): electron-builder сравнивает имена файлов буквально, и без `en-US` на Windows/Linux удалился бы запасной `en-US.pak`. Язык приложения теперь берётся из списка ОС, если Chromium откатился на en-US (`src/main/systemLocales.ts`). dmg (UDZO, один и тот же пакет) 146,2 → 130,0 МБ (−16,3 МБ, −11 %).
3. **`encode zstd gzip` для `@api` в Caddy.** Сейчас JSON `/api/*` отдаётся без сжатия. Ranged/blob-ответы исключить по content-type. ✅ **Сделано:** только `application/json*`, пути `/gateway`, `/api/files/*`, `/api/unfurl/image` исключены. `caddy validate` на тестовых хостах, Range у файлов (206) не тронут.
4. **Не перезагружать закрепы при каждом открытии комнаты.** Они и так обновляются живыми событиями через `updatePins`. Перезагружать только при первом открытии и после resync гейтвея. ✅ **Сделано:** за 105 переключений `GET …/pins` 104 → 1, всего REST 156 → 46.
5. **Autovacuum по вставкам для `messages`** (`autovacuum_vacuum_insert_scale_factor = 0.05`). Подсчёт непрочитанного по индексу без VACUUM даёт 150 мс, после VACUUM 10,6 мс. ✅ **Сделано:** миграция 00030 (`scale_factor 0.05`, `threshold 1000`), Down сбрасывает.
6. **Ленивый `Tip`.** Radix Tooltip монтировать только при hover/focus. Сейчас это ≈ 40 % всех рендеров компонентов в ленте. ✅ **Сделано:** рендеры компонентов на 20 сообщений 83 457 → 37 003 (−56 %), на 21 переключение 141 654 → 58 111 (−59 %). Поведение и `aria-describedby` проверяет тест `tooltip-lazy`: он проходит и на старом, и на новом `Tip`.
7. **Не писать `typing` в resume-буфер Redis.** Ожидаемо −30–50 % операций Redis при активном наборе. ✅ **Сделано:** TYPING_START уходит с seq 0 и не попадает в буфер. Экономия — 1 запись буфера (до 5 команд Redis) на получателя на каждое событие.
8. **`room.prepareConnection(url, token)`**, когда пользователь выбирает голосовую комнату или наводит на неё. Ожидаемо −100–300 мс до входа (оценка, не замерено). ⏸ **Не сделано:** токен выдаёт только `/join`, а на hover его звать нельзя (он создаёт pending). Без токена `prepareConnection` — это `HEAD` на rtc-хост. Замер WSS к `rtc.calab.ru` (6+6 холодных браузеров): 272 → 259 мс медиана, разница в пределах шума, потому что WebSocket открывает новое TLS-соединение. На моке (localhost) выигрыш нулевой по построению.
9. **Ленивые окна админки, настроек и онбординга** (`React.lazy`). Сейчас это ≈ 130 КБ исходников в стартовом чанке. ✅ **Сделано:** `lib/lazyPreload.tsx`; окна подгружаются в простое после READY и при наведении на кнопку настроек. Главный чанк 2 147 → 2 036 КБ (−108 КБ), компиляция 25,7 → 22,9 мс.
10. **Исключить `**/*.map` из asar.** Там 52 карты из node_modules updater-а; выигрыш копеечный, риска нет. ✅ **Сделано:** в asar 0 карт.

Обход исправлен: `Bubble` на typing/presence не рендерится (0). Абсолютные числа рендеров в шагах 6 и выше завышены, но соотношения «до/после» одного инструмента это не меняет.

Не находки, проверено:
- Превью картинок и unfurl при повторном открытии комнаты перезапрашиваются: 28 за 105 переключений. Сервер отдаёт `immutable` / `max-age`, поэтому это попадания в HTTP-кэш, а не сеть.
- Вторая копия `@bufbuild/protobuf` в бандл не попадает. Дубли в lockfile (semver, fs-extra, minimatch…) — только dev и сборка.

## Что уже хорошо

- **Старт.** Медиана из 3 холодных запусков на моке (probe, M4, ОС-кэш тёплый): окно 0,31–0,52 с, сайдбар после READY 0,56–0,88 с, DCL 110–160 мс, FCP 156–212 мс. Main-процесс лёгкий: 100 КБ, синхронно читает только настройки и сессию `safeStorage`.
- **Память.** 105 переключений комнат: heap 14,4 → 15,3 → 15,7 → 16,0 МБ (после 0/21/42/105), рост затухает. DOM-узлы (563) и JS-слушатели (433) не растут. ResizeObserver пересоздаются (≈ 6 на переключение), но все отключаются: наблюдаемых всегда 8. Blob-URL без звонка не создаются. Сообщения обрезаются (`trimWindow`).
- **Таймеры без звонка:** два `setInterval` — sweep 60 с и суточный. `TypingIndicator` 1 с живёт только пока кто-то печатает (как в docs/14).
- **Бандл.** Prism по языкам, транскрипт, локали en/es/zh, RNNoise-worklet (1,8 МБ) и opus-recorder (380 КБ) грузятся лениво. lucide-react tree-shaken (51 КБ). Emoji-данных в бандле нет.
- **Сервер.** В READY нет N+1: ≈ 6 запросов на пространство, вложения и реакции батчем `ANY(ids)`, последние сообщения через LATERAL. Fan-out кодирует событие один раз на инстанс. Непрочитанное ограничено 999 и считается index-only.
- **Протокол.** Typing троттлится с двух сторон: клиент не чаще 1/3 с на комнату плюс token bucket, сервер `SET NX EX 3s`.
- **Раздача.** Статика с хэшем — `immutable` + zstd, HTML — `no-cache`. На `releases.calab.ru` есть `.blockmap` и Range, поэтому дифференциальные обновления работают. Размеры 0.6.2: mac arm64 dmg 131 МБ, x64 138 МБ, Windows exe 115 МБ, AppImage 128 МБ, deb 102 МБ.
- **LiveKit совпадает с docs/02.** `adaptiveStream` и `dynacast` включены, `webAudioMix: false` (правило эха), `autoSubscribe: false`, DTX включён, RED opt-in, у камеры и экрана SVC simulcast L1T3. Безопасно включить больше нечего. `singlePeerConnection` — только после проверки сервера.

## Как повторить

```sh
pnpm -F @calaba/desktop build:app            # out/ (без electron-builder)
npx tsx tools/perf-probe.ts --port 39377 --launches 3 > probe.json
```

`tools/perf-probe.ts` запускает продовый renderer против мок-API на своём порту и во временном `userData`. Он выдаёт:
- тайминги холодного старта;
- рендеры компонентов по событиям (сообщения, typing, presence, переключение комнат), через хук React DevTools в продовой сборке;
- причину рендера для `Bubble`, `Feed` и `Sidebar`;
- инвентарь `ResizeObserver` / `setInterval` / blob-URL;
- heap и DOM-счётчики после 21/42/105 переключений;
- дубли REST.

Один тестовый Electron за раз (CLAUDE.md). Бандл: `npx electron-vite build --sourcemap` + `npx source-map-explorer out/renderer/assets/index-*.js --json`. Серверные EXPLAIN — на отдельной dev-базе с синтетикой: 40 участников, 30 комнат, 200 тыс. сообщений, `VACUUM ANALYZE`. База после замера удалена.
