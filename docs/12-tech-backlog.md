# Технический бэклог (сервер / инфра / тесты)

Сюда попадают minor-находки ревью и не-блокеры релиза (правило CLAUDE.md «Одно ревью на изменение»). Формат: дата · где · что · почему не сейчас.

- 2026-09-26 · `apps/server/internal/rtc/sync.go` `reconcileStreams` · нет grace-окна (в отличие от `joinGrace` для состояний): стрим из `track_published`, пришедшего между `ListParticipants` и `voice.Streams`, удаляется (VOICE_STREAM_STOP ENDED) и добавляется обратно следующим тиком — клиенты видят «моргание». Фикс: снимок стримов до листинга или проверка `startedAt > start − joinGrace`. Не блокер 0.1.1 (поведение существовало с v0.1.0, окно 30 с × редкое совпадение); сделать в 0.1.2 отдельным агентом с интеграционным тестом.
- 2026-09-26 · `internal/events` · при зависшем Redis guest cleanup ограничен 5 с + 3 с на гостя с живыми сессиями, logout-all — до ~6 с. Приемлемо; пересмотреть, если появятся жалобы на задержку logout.
- 2026-09-26 · `visual-nightly.yml` · после разделения на test/publish не проверялся живым запуском — проверить по первому ночному прогону.
- `rtc/camera.go cameraStarted` не проверяет `CameraBlocked`: при переупорядоченных webhook запись камеры заблокированного устройства может появиться до reconcile (grant камеру не даёт — `CameraHeld` учитывает блок).
- Смена `camera_limit` на 0 (комната/workspace) не останавливает уже включённые камеры — действует только на новые `/camera/request`.
- `users.ValidateTimezone`: на case-insensitive ФС (macOS dev) `Europe/MOSCOW` проходит; в distroless (tzdata) — нет. Сравнивать с `loc.String()`.
- `rtc/camera.go stopOwnCamera` требует `rooms.Access`: при потере VIEW_ROOM во время звонка свою камеру через API не остановить (резерв живёт до выхода / TTL 10 мин).
- 2026-09-26 · `apps/desktop/src/main/ptt.ts` · если закрыть настройки во время захвата Caps Lock, ремап caps→F18 остаётся до смены биндинга/выхода; снимать ремап при закрытии окна настроек/отмене захвата (unmount). Не блокер.
- 2026-09-26 · `apps/desktop/e2e-web` · `move.web.spec` проходит против мока только на свежем состоянии: `app.web.spec` создаёт то же пространство «E2E web», и slug занят — сделать переиспользование по slug в `move.web.spec` (как в app.web) или уникальные имена на прогон.
- 2026-09-26 · DM (ADR-0020) · `PRESENCE_UPDATE` / `USER_UPDATE` peer идут только через общие пространства: у DM без общего пространства presence и смена профиля peer не доходят до READY. Решение — рассылать их и DM-peer’ам (кэш списка DM в gateway), когда появится UI «Личные».
- 2026-09-26 · DM · файлы DM не ограничены квотой (только общий потолок сервера и 1 GiB неприкреплённых на пользователя); при росте — пользовательская квота.
- 2026-09-26 · `apps/server/internal/dms/dms.go` create · гостевой аккаунт получателя → `403` проверяется до общего пространства: по id (uuidv7, не угадывается) можно узнать, что это гость. Перенести проверку после `ShareWorkspace` (для чужих — `404`). Minor.
- 2026-09-26 · `apps/desktop/src/main/capture.ts` `MAC_SYSTEM_AUDIO_FEATURES` · в Chromium 152 (Electron 44.4.5) нет фич `MacLoopbackAudioForScreenShare` / `MacSckSystemAudioLoopbackOverride` (проверено по строкам фреймворка, вместо них `MacCatapLoopbackAudioForScreenShare`, Core Audio Tap). Флаги сейчас ничего не включают; системный звук на macOS работает по умолчанию. Проверить `MacCatapLoopbackAudioForScreenShare` — возможно, он исключает звук своего процесса (echo rule 4), — отдельной задачей с живым тестом. Не блокер.
- 2026-09-26 · `apps/server/internal/gateway` · `dmPeers` кэш сессии: отрицательные ответы для произвольных room id (≤ 1024) живут до конца сессии; при удалении DM (v2) нужна инвалидация. Minor.
- 2026-09-26 · docs/09 #20 · серверного deafen нет (только server mute): пункт «Заглушить звук для всех» в меню участника не показан. Нужны `VoiceState.server_deafened`, `POST …/voice/{userId}/deafen|undeafen` (MUTE_MEMBERS) и grant `canSubscribe=false` через `UpdateParticipant`. Отдельной задачей.
- 2026-09-26 · `e2e-visual/mobile.visual.spec.ts` · `m-drawer` и `m-dm-list` расходятся с эталоном на 1–2 % (данные участников/нижней панели) на main bfe76ee — нестабильная фикстура; перезаписать/стабилизировать при следующем мобильном изменении.
- 2026-09-27 · ревью ADR-0024 · `rtc/webhook.go streamStarted/cameraStarted` · лимит качества плана (пресет/fps стрима и камеры) — только в ответе `/stream|camera/request` и в UI: модифицированный клиент может опубликовать 1080p/60 на Free. Проверка `width/height` из `track_published` не спасает (их сообщает сам клиент в AddTrack), grant LiveKit разрешение не ограничивает. Приемлемо для монетизации (обход только патченым клиентом); при необходимости — проверка слоёв через LiveKit Egress/Stats или `UpdateSubscription` quality cap на SFU. Minor.
- 2026-09-27 · ревью ADR-0023/0024 · `plans/admin.go guard` + без SMTP · на сервере без SMTP адрес при регистрации/смене сразу «подтверждён», поэтому адрес из `SUPERADMIN_EMAILS`, ещё не зарегистрированный, может занять кто угодно. На стенде SMTP есть; для self-hosted — предупреждение в `config.Validate` (SUPERADMIN_EMAILS без SMTP_HOST) или требовать зарегистрированного владельца до старта. Minor.
- 2026-09-27 · ревью ADR-0024 · `/api/admin/*` без токена отвечает 401 (auth до guard), неизвестный `/api/*` — 404: существование админ-API видно анонимно. Для скрытия — обёртка «нет/невалидный токен → 404» только для admin-маршрутов. Minor.
- 2026-09-27 · ревью ADR-0023 · `auth/email.go ResetPassword` · известный адрес без живого кода делает на один UPDATE больше, чем неизвестный (argon2 выровнен); разница ~1 мс на фоне ~30 мс хэша. Minor.
