# 08 — Дизайн и UX

Цель: интерфейс ощущается нативным, быстрым, лаконичным. **Визуальный язык — macOS (Apple HIG)**: структура как у Discord, но внешний вид как у системных приложений Apple — Messages/FaceTime/Finder: сдержанные цвета, много воздуха, чёткая иерархия, материал «стекло» (vibrancy) на панелях, один акцентный цвет, ничего декоративного. Ничего лишнего: каждый элемент отвечает на вопрос «зачем он здесь».

## Принципы Apple HIG, которые применяем
- **Ясность**: текст читается на любом фоне, иконки однозначны, приоритет — содержимому (сообщения, участники), а не хрому.
- **Уважение к содержимому**: панели полупрозрачны и уходят на второй план, контент — непрозрачен и контрастен.
- **Глубина**: слои (sidebar → контент → плавающие панели → модалки) различаются материалом и тенью, а не рамками.
- **Системность**: используем системный шрифт (SF Pro на macOS через `-apple-system`), системный акцентный цвет по умолчанию (`accent-color`/`AccentColor`), нативные скроллбары (overlay), нативные контекстные меню там, где это Electron main (tray), и стилизованные под macOS — в renderer.
- **Предсказуемость**: элементы управления выглядят как системные (кнопки 28 px, поля с radius 6, переключатели-toggle, сегментированные контролы), располагаются там, где их ждут (действия справа, отмена слева от подтверждения на macOS).

## Система

- **Токены** — только через CSS-переменные (`--color-*`, `--space-*`, `--radius-*`, `--shadow-*`, `--blur-*`), определены для dark и light. Никаких цветов/размеров «в лоб» в компонентах.
- **Сетка отступов** — 4 px: `--space-1..8` = 4/8/12/16/20/24/32/40. Внутренние отступы карточек и панелей — 12/16, между секциями — 24, край окна — 16. Строки списков — 32/36 px высотой, кликабельная область не меньше 32 px.
- **Типографика** — системный стек (`-apple-system, BlinkMacSystemFont, Segoe UI, Inter, Roboto`), шкала как в HIG: 11 (caption), 12 (footnote), 13 (body в списках), 14 (body), 16 (headline), 20 (title), 26 (large title в онбординге); веса 400/500/600; line-height 1.35–1.45; `-webkit-font-smoothing: antialiased`. Моноширинный — SF Mono/Menlo для кода.
- **Радиусы** — **pill (full)** для кнопок, полей ввода, сегментированных контролов, чипов, бейджей и поисковых полей (решение владельца 26.09: «скруглённые формы смотрятся круче»); 8 (карточки), 12 (панели/модалки/PiP), full (аватары). Исключения — только там, где pill ломает сетку: кнопки в тулбарах-иконках (квадратные icon-only 28×28 остаются с радиусом 8), строки списков.
- **Материалы (как в macOS)** — три уровня:
  - `sidebar` — WS-бар и колонка комнат: на macOS настоящий vibrancy окна (`BrowserWindow` с `vibrancy: 'sidebar'`, `transparent` фон у этих колонок), на Windows/Linux/web — полупрозрачный фон + `backdrop-filter: blur(20px) saturate(180%)`;
  - `toolbar` — заголовок комнаты, панель «я», композер: стекло `blur(12px)`, фон 0.7–0.8 непрозрачности;
  - `popover` — PiP-плитка стрима, модалки, поповеры, context-menu, тосты: стекло `blur(20px)`, граница `1px` с 8 % белого (dark) / 6 % чёрного (light), тень мягкая двухслойная.
  - `sheet` — модальные окна (настройки, диалоги): **непрозрачный** материал, аналог macOS sheet — сквозь стекло просвечивал контент и мешал читать.
  Область сообщений — **непрозрачная** (читаемость). Fallback без `backdrop-filter` — сплошной фон. Уменьшение прозрачности (`prefers-reduced-transparency`) — сплошные фоны.
- **Слои (z-index)** — фиксированная шкала: base 0, sticky 10, pip 20, popover 30, modal 40, toast 50. Элемент одного слоя никогда не перекрывает другой того же слоя без явного порядка.
- **Motion** — 120–180 мс, `ease-out`; только opacity/transform; `prefers-reduced-motion` → без анимаций. Нет анимаций «ради красоты».
- **Состояния** у каждого интерактивного элемента: default / hover / active / focus-visible (кольцо 2 px) / disabled / loading. Фокус клавиатурой виден всегда.
- **Иконки** — SF Symbols-подобный стиль: один набор (Lucide как ближайший кроссплатформенный), 16/20 px, stroke 1.5–1.75, монохромные, цвет наследуется от текста; акцентный цвет — только для активного состояния.
- **Цвет** — один акцент (системный синий `#0A84FF`/`#007AFF`); **заливка акцентом с белым текстом — только `accent-strong` `#0071e3`** (4.7:1; на `#0A84FF` белый даёт 3.64:1); ссылки — `accent-text`; красный **текст** — отдельный токен `--color-danger-text` (`#ff7f75` dark / `#b0000d` light), иконки/точки — системный красный; нейтральная серая шкала с лёгким холодным оттенком, семантические: зелёный (говорит/онлайн), жёлтый (idle/предупреждение), красный (dnd/ошибка/стрим live). Никаких градиентов и «брендовых» подсветок.

## Layout

```
┌──┬──────────┬───────────────────────────────────┐
│WS│ Комнаты  │ Заголовок комнаты (стекло)        │
│  │          │───────────────────────────────────│
│  │          │ Сообщения                 [PiP]   │
│  │          │                                   │
│  │──────────│───────────────────────────────────│
│  │ Панель я │ Композер                          │
└──┴──────────┴───────────────────────────────────┘
```

- **Слои окна (v0.2, как в новом Discord):** заголовок окна и рейл — один слой окна (материал `rail`). Колонка комнат и чат — «остров» поверх него: верхний левый угол 12 px, hairline по верхнему и левому краю. Разделитель под заголовком пространства идёт на всю ширину колонки.
- **Нижний островок** (как в Discord): «Голос подключён», плашка обновления и панель «я» — один плавающий блок на всю левую часть, от левого края рейла до правого края колонки комнат. Отступ 8 px от краёв и снизу, радиус 12. Лежит на слое окна: материал `toolbar`, тень `--shadow-island`, секции разделены hairline. Рейл и список комнат заканчиваются над ним (их нижний отступ — `--island-height` + 20 px). Без голоса в нём только панель «я».
  - **Панель «я»:** высота 52 px, аватар 32 по центру по вертикали с точкой статуса 12 px (обводка 2 px цвета фона, наезжает на аватар — см. «Точка присутствия»). Имя 14/600, статус 13 secondary; длинное имя и статус затухают у правого края (`.fade-end`), без «…». Контролы — микрофон ▾, наушники ▾, настройки: иконки 20 px в зоне 32×32. У микрофона и наушников ▾ 12 px рядом с иконкой, в общей зоне наведения. Контролы на расстоянии 12 px друг от друга, до правого края 12 px.
    - **Меню статуса** (docs/09 #29, референс `discord-status-menu.png`): клик по аватару/имени — меню 280: шапка (аватар 40, имя, email) | «В сети» | «Не активен» › · «Не беспокоить» › (подпись «Уведомления и звуки не приходят») · «Невидимый» › («Вас увидят офлайн»); подменю — 15 минут · 1 час · 8 часов · 24 часа · 3 дня · Навсегда (клик мышью по самой строке — «Навсегда»); у выбранного — ✓ и «до 18:30»; по истечении — «В сети» (`prefs.presenceUntil`, таймер клиента). Ниже — свой статус с «Очистить» или «Задать свой статус…» (sheet: эмодзи + текст + «Очистить через»), затем «Редактировать профиль».
    - **Точка присутствия** (везде, где `Avatar presence`): диск ≈ 0,375 аватара (12 px на 32, ≤ 20), вырез-обводка 2 px (4 px от 56) цветом поверхности (`ring`), центр — на окружности аватара под 45° справа снизу. Глиф: зелёный диск — в сети, жёлтая луна — не активен, красный с поперечной чертой — не беспокоить, серое кольцо — офлайн/невидимый.
    - **Меню микрофона ▾** (docs/09 #28): сверху «Режим» — радио «По голосу» (под ним порог активации) / «Push-to-talk» (под ним строка клавиши: pill с текущей клавишей и «Изменить…», и компактный ползунок «Задержка отпускания»); выбор режима меню не закрывает. Ниже через hairline — «Устройство ввода» и «Настройки голоса».
    - **Захват клавиши в меню**: клик по строке — pill «Нажмите клавишу…» с акцентной рамкой и «Esc — отмена», ниже «Последняя нажатая клавиша» (Electron). Пока идёт захват, меню не закрывается (клик снаружи игнорируется, Esc отменяет только захват), клавиши не уходят в typeahead/пункты; закрытие меню отменяет захват.
    - **Мобильная полоса звонка**: кнопка «Ещё» 40 px — «Режим микрофона» (По голосу / Push-to-talk) и «Настройки голоса»; клавишу на телефоне не назначаем (есть кнопка удержания PTT).
  - **«Голос подключён»:** шапка — сигнал (36×36, клик → детали связи), «Голос подключён» 14/600 зелёный и «Комната / Пространство» 13 secondary, справа кнопка шумоподавления (волна 20 px в зоне 32×32; включено — заливка акцентом 20 % и акцентная иконка) и красная «отключиться». Под ней три кнопки одинаковой ширины высотой 36 px с промежутком 10 px: Камера ▾ / Экран / Ещё. Панель не сворачивается.
  - **Поповер шумоподавления** (Discord): открывается справа от островка, нижним краем на уровне кнопки, растёт вверх и не перекрывает островок; ширина 320, отступы 16. Заголовок «Шумоподавление» 15/600 с тумблером (тот же `prefs.rnnoise`, что в «Голос и устройства»), описание 13 secondary, «Проверка микрофона»: «Проверить» + индикатор из 24 сегментов 4×20 (зелёные слева, линейно −60…0 dBFS, уровень после RNNoise). Проверка — 3 с записи отдельным захватом (устройство и шумодав из настроек, не зависит от mute/PTT), затем воспроизведение себе через обычный `<audio>` на устройстве вывода (правила эха, docs/02), индикатор повторяет записанные уровни; закрытие поповера останавливает проверку. Внизу через hairline — «На базе RNNoise · Подробнее» (ссылка на docs/02).
- WS-бар 64 px, колонка комнат 240 px (min 200, max 320, тянется), чат — остальное, min-width окна 960×600. Правая колонка участников (240 px) — колонка от 1200 px ширины окна; уже — плавающая панель над чатом (закрыта по умолчанию, Esc закрывает).
- Ничего не наезжает: длинные имена — `text-overflow: ellipsis` + tooltip; списки — виртуализированы; PiP не перекрывает композер и последние сообщения (отступ снизу = высота композера + 16).
- **Выбор источника стрима** (docs/09 #17): лист 900×600, вкладки «Весь экран» · «Приложения», «Весь экран» — первая и по умолчанию, выбран первый экран. Один источник — одна крупная карточка 16:9 по центру области (ширина ≤ 60 % и не выше области), несколько — две колонки фиксированной ширины с промежутком 12. Превью запрашивается ровно под бокс карточки × `devicePixelRatio` и рисуется 1:1 (`object-fit: contain`), при ресайзе — перезапрос через 250 мс. Выбранная карточка — заливка акцентом 14 % и рамка 2 px акцентом **внутрь** (`ring-inset`), не выходит за карточку.
- **Свой стрим и полный экран** (docs/09 #18): свой стрим выглядит как чужой (плитка, stage, PiP, pop-out), вместо LIVE — красный бейдж «Вы стримите», в панели управления вместо качества/громкости — отправляемый пресет («1080p · 15 fps»). «На весь экран» — нативный полноэкранный режим окна (macOS — отдельный Space) с раскладкой «только видео»: одна тонкая полоса сверху 44 px (`black/60`): чип стримера, качество/fps, звук, «Свернуть»; полоса и курсор прячутся через 2 с без движения мыши и возвращаются по движению/клавише. Выход — «Свернуть», Esc, ⌃⌘F или зелёная кнопка; окно возвращается к прежним размеру и раскладке. Pop-out окно стрима — та же полоса с «На весь экран».
- **Список комнат (docs/09 P1 #19, как в Discord):** без встроенных секций — сначала комнаты без категории плоским списком (без заголовка), затем пользовательские категории (заголовок 11/600 uppercase, сворачивание запоминается, двойной клик или меню — переименование прямо в заголовке, Enter/уход фокуса сохраняет, Esc отменяет). С `MANAGE_ROOM` строки и заголовки категорий перетаскиваются мышью (порог 6 px): строка-источник 40 % непрозрачности, за курсором — плашка комнаты, место вставки — линия акцента 2 px между строками (без сдвига списка); верхняя половина заголовка категории — конец контейнера над ним, нижняя — начало категории; список автопрокручивается у краёв, Esc отменяет. Применяется сразу, при отказе сервера — откат и тост. Клавиатурная альтернатива в меню комнаты: «Переместить вверх/вниз» (на краю — в соседний контейнер), «В категорию ›»; у категории — «Переместить вверх/вниз». На телефоне перетаскивания нет (только меню). Меню пустого места списка и ▾ пространства: «Скрыть заглушённые» ☐ (открытая комната и моя голосовая остаются) · «Создать комнату» · «Создать категорию» · «Пригласить».
- Пустые состояния — короткий текст + одно действие («Создайте первую комнату»).
- Ошибки — inline рядом с полем или тост; никаких `alert()`.

## Личные сообщения (ADR-0020)

- **Рейл:** бейдж «в голосе» у плитки пространства — зелёный круг 16 px с иконкой динамика и обводкой 2 px цвета рейла, справа сверху (Discord).
- **Колонка комнат (Discord 2x):** строка комнаты 34 px, название 15 px; карточка активной голосовой комнаты — та же типографика, таймер и счётчик на одной линии с названием (строка 20 px, по центру, `tabular-nums`), статус 13 secondary. Участники голосовой комнаты — строка 28 px, аватар 24 (кольцо речи внутри габарита), начинается там же, где название комнаты (32 px от края строки), 8 px до имени; имя 14 regular (говорящий — primary, остальные secondary), «(+3 UTC)» тем же кеглем secondary; иконки mute/deaf/камера 16 px и LIVE справа. Строка «Пригласить в комнату» — та же сетка (28 px, пунктирный круг 24).
- **Рейл (DM):** первая плитка — «Личные» (иконка приложения, как Home в Discord), под ней разделитель, потом пространства. Пилюля слева — как у пространств (активно / непрочитано); красный счётчик — непрочитанные сообщения во всех DM (каждое сообщение DM — как упоминание). Гостевым аккаунтам плитки нет.
- **Колонка слева** (тот же материал, ширина и нижний отступ под островок, что у колонки комнат): сверху поле-кнопка «Найти или начать беседу» (pill, открывает «Новое сообщение»), затем заголовок секции «Личные сообщения» с «+» и строки 46 px: аватар 32 с присутствием, имя 15 (жирное при непрочитанном) и время справа (сегодня — ЧЧ:ММ, «вчера», иначе «14 янв.»), ниже последнее сообщение 12 («Вы: …» для своих) и красный счётчик. Сортировка — по последней активности. Контекстное меню: «Отметить прочитанным», «Копировать ссылку» (`https://<сервер>/dm/<id>`).
- **Без открытой переписки** справа пустое состояние: иконка, «Личные сообщения», одна строка и кнопка «Новое сообщение». Переписка сама не выбирается.
- **Чат DM** — та же лента и композер, что у комнаты (вложения, реакции, ответ, закрепы — закрепляют оба). Заголовок: аватар 28 с присутствием, имя собеседника, • присутствие и статус (или «… печатает»); справа поиск в переписке, закреплённые, уведомления. Нет колонки участников, голоса, настроек и поиска по пространству. Начало истории — аватар 56 и имя; плейсхолдер композера — «Написать @Имя».
- **Телефон (≤ 768 px, ADR-0021):** «Личные» в шторке (☰) — рейл + колонка DM вместо колонки комнат; открытая переписка на весь экран, в заголовке ☰, аватар, имя, поиск и уведомления (закреплённые — в полосе под заголовком), шторки участников нет.
- **Меню участника и профиль** (docs/09 #20, Discord): одно меню везде — строки в списке комнаты, колонка участников, аватар и имя автора в чате, «…» в профиле. Разделы через hairline: Профиль · Упомянуть · Написать · Добавить заметку (вторая строка «Видна только вам») | для меня: «Громкость» 0–200 % (`el.volume` ≤ 1: выше 100 % только компенсирует общую громкость, иначе подпись под ползунком), «Заглушить для меня» ☐ (у участника — иконка `VolumeX` «Вы заглушили»), «Не слышать» ☐, «Не показывать видео» ☐ | ник · Роли › · Переместить в › | модерация красным (серверный mute ☐, камера, отключить) | админ | Копировать ID. **Профиль** — sheet 440: баннер 88 px цветом аватара, аватар 80 с присутствием на краю баннера в кольце цвета sheet, имя 20/600 + «(+N UTC)», ник/имя профиля, статус; кнопки 32 px «Написать» (акцент) · «Упомянуть» · «…»; секции (заголовок 12/600 secondary): «Участник с» (иконка Calab + дата · иконка пространства + дата), «Роли» — pill-чипы с точкой цвета роли, × и «+» по правам, «Заметка (видна только вам)» — поле без рамки (hover/focus — заливка), растёт по тексту, сохраняется через 800 мс после ввода и при уходе из поля, статус «Сохранено» справа от заголовка. Клик по участнику — прежняя карточка-поповер с кнопкой «Открыть профиль».

Снимок `voice-room-recording`.

- Всё, что меняется в реальном времени (говорит, стримит, печатает), обновляется без перерисовки соседей.
- **Роли в списках** (docs/09 #26): один компонент `RoleMark` (`features/people/MemberBits.tsx`) — корона у владельца, щит 14 px у админа, tooltip «Владелец»/«Администратор»; имя в цвете роли (`--color-role-owner` золотой, `--color-role-admin` акцент, участник/гость — `text-fg`; light ≥ 4.5:1) — колонка участников (offline — muted), строки голосовой комнаты, карточка и лист профиля, DM-шапка (старшая роль среди общих пространств, tooltip «Роль · Пространство»), упоминания, быстрый поиск (на выделенной строке — цвет текста строки). Кольцо речи — на аватаре, цвет роли — на имени: у владельца/админа в голосовой строке имя всегда цвета роли.
- **Иконки состояния голоса** — 16 px справа в строке: перечёркнутый микрофон (серый; серверный mute — красный), при deafen — микрофон и затем перечёркнутые наушники (Discord); то же во второй строке колонки участников.
- **Настройки пространства → Участники**: сверху pill-поиск (ник или имя профиля) и сегменты роли «Все / Владелец / Админы / Участники / Гости»; ник редактируется в строке (✎ при hover/фокусе или двойной клик) для тех, у кого право переименовывать (как «Изменить ник» в меню): Enter/уход из поля — сохранить, Esc — откат (окно не закрывает), ошибка — строкой под полем. Снимок `settings-members`.
- **Индикация речи** (Discord): у говорящего — кольцо 2 px `--color-green` вокруг аватара (`outline` с зазором 2 px, `.speak-ring`, размер не меняется, fade 100 мс; в строках участников под голосовой комнатой — внутри аватара 24 px: `inset` 2 px + зазор 1 px, `.speak-ring-inset`, ничего не выступает за строку) и имя `text-fg` вместо `text-muted`; у неговорящих, включая себя, — обычный muted. Везде, где аватар участника звонка: строки под voice-комнатой, колонка участников, карточка профиля, панель «я», мобильная полоса звонка; плитка камеры — то же кольцо внутри плитки.
- Источник: remote — LiveKit `ActiveSpeakersChanged` OR локальный уровень входящего звука (`getSynchronizationSources`, docs/02 «Индикация речи собеседников»; по userId: любое устройство человека), себя — локальный VAD/PTT (`transmitting`), не сервер. Появляется сразу, гаснет через 200 мс после речи (без мерцания); обновления store батчатся (≤ 1 раз в 50 мс), подписка — на одного участника (`s.speaking[id]`). Замьюченный не подсвечивается.
- **Подключение к голосу** (оптимистичный вход, docs/05): по клику я сразу в списке комнаты, у остальных тоже. Строка участника с `pending` — обычная, без спиннеров.
- Если `pending` держится дольше 3 с, вокруг аватара появляется кольцо «подключается» (`.connect-ring`): 2 px на месте кольца речи, дуга muted → accent, оборот за 1,2 с; при `prefers-reduced-motion` кольцо статичное. Tooltip «Подключается…».
- Кольцо речи на время подключения не показывается. Состояние одно и то же в строках под комнатой, колонке участников и мобильной полосе звонка.
- Таймер звонка в карточке моей комнаты и «Голос подключён» — зелёные, пока я подключён.
- Индикатор качества связи — всегда виден, пока в voice; клик → детали.
- **Уведомления** (docs/09 п. 22): колокольчик в шапке комнаты — меню «Как в пространстве (<уровень>) / Все сообщения / Только упоминания / Ничего» и «Заглушить: На 1 ч · На 8 ч · До утра (08:00) · Навсегда»; иконка: `Bell` по умолчанию, `BellRing` при «Все сообщения», перечёркнутая `BellOff` при «Ничего» или заглушённой комнате/пространстве. В DM — «Все сообщения / Ничего». В меню пространства «Уведомления…» — то же для пространства («По умолчанию для комнат»). Заглушённые комнаты/пространства не показывают точку непрочитанного и жирное имя (строка, рейл, «Личные») — только счётчик упоминаний. Бейдж приложения (Dock, счётчик, подсказка трея, заголовок окна, PWA) = упоминания + непрочитанные DM, не все непрочитанные.
- Настройки — как System Settings: окно с левым списком разделов и иконками, справа — группы в скруглённых карточках, строка = «название слева, контрол справа»; изменения применяются сразу, без кнопки «Сохранить» (кроме смены пароля/email).
- Звуки событий (Настройки → Уведомления → Звуки): строка на событие — «▶ прослушать» и тумблер. «Новое сообщение» — WAV из `apps/desktop/scripts/gen-sounds.mjs` (двухтоновый «о-оу», −14 LUFS): чужое сообщение только в DM и в комнатах с эффективным уровнем «Все сообщения» (упоминание — звук «Упоминание»), с учётом mute комнаты/пространства и «не беспокоить»; под строкой подсказка со ссылкой «Где настроить» (открывает колокольчик комнаты), не чаще 1 раза в 2 с; в открытом чате при фокусе окна — «Тихо» или «Выкл.» (по умолчанию). Только через `<audio>` (docs/02).
  - **«Голос и устройства» → «Колонки и эхо»** (docs/02 «Эхо: колонки»): строка «Как вы слушаете» — сегментированный контрол «Наушники» (по умолчанию) / «Динамики» / «Авто»; подсказка под названием меняется с выбранным режимом и говорит, что будет с микрофоном. Строка «Проверка эха» — кнопка «Проверить» (secondary, busy 3 с), результат строкой под ней: «Эхо не обнаружено» (`text-ok`), «Слабое эхо …» (`text-warn`), «Сильное эхо …» (`text-danger-text`), каждый с советом. Во время звонка кнопка неактивна, подсказка «Недоступна во время звонка». Настройка локальная для устройства (ноутбук на колонках, стол с наушниками).
  - Тост «Похоже, собеседник слышит себя…» — info, один раз за звонок, с действием «Включить «Динамики»» в режиме «Наушники».
- Порядок кнопок в диалогах — как на macOS: основное действие справа (акцентное), «Отмена» слева от него; деструктивное — красным текстом. Заголовок диалога 16/600, текст 13, отступы 20.
- Заголовок окна на macOS — `titleBarStyle: 'hiddenInset'`, светофоры в WS-баре, область под перетаскивание (`-webkit-app-region: drag`) на верхней полосе.
- Тексты — коротко, глаголом, без канцелярита: «Войти», «Создать комнату», «Начать стрим». Без восклицаний.

## Онбординг (первый запуск)

Шаги, каждый — один экран, можно пропустить всё, кроме входа:
0. **Язык** — только если язык не выбран явно и ОС не русская (см. «Язык»).
1. **Сервер** (только если не задан) → **Вход / регистрация**.
2. **Микрофон**: запрос разрешения → выбор устройства → живой индикатор уровня → «Слышно хорошо». При отказе — объясняем, как включить в настройках ОС (deep link `x-apple.systempreferences:` на macOS / `ms-settings:privacy-microphone` на Windows).
3. **Режим микрофона**: VAD (по умолчанию) или PTT; для PTT на macOS — объяснение про Input Monitoring с кнопкой «Открыть настройки», проверка статуса после возврата.
4. **Стрим экрана** (опционально, можно позже): на macOS — Screen Recording; показываем, что после выдачи нужен перезапуск приложения, если ОС этого требует.
5. **Уведомления** (опционально).
6. **Готово** → первый workspace: создать или войти по инвайту.

Разрешения запрашиваются в момент, когда они нужны, с одной фразой «зачем». Статусы разрешений видны в Настройки → Устройства с кнопками «Открыть настройки ОС».

## Язык (ADR-0022)

- **Локали**: `ru` (источник правды), `en`, далее `es`, `zh-CN`. Словари — `apps/desktop/src/renderer/i18n/<locale>/*.ts`; `ru` вшит в бандл, остальные — ленивые чанки; нет папки локали → английский, без ошибок. Термины — `docs/i18n-glossary.md`.
- **Определение**: сохранённый выбор (`prefs.locale`) → языки ОС (`app.getLocale()` + системный список в Electron, `navigator.languages` в вебе) → ru/uk/be/kk → `ru`, zh* → `zh-CN`, es* → `es`, иначе `en` (берём первый язык списка, который умеем сопоставить).
- **Выбор**: «Настройки → Приложение → Язык» (есть и в вебе): «Как в системе» + названия языков на самих языках (Русский, English, Español, 中文（简体）). Переключение без перезагрузки; `<html lang>` обновляется; трей и системные уведомления main получает переведёнными (`app:set-strings`).
- **Правила кода**: никаких строк в компонентах — только `t('key', params)`; число + слово — только `plural('key', n)` (формы в словаре по категориям `Intl.PluralRules`), склейка форм в коде запрещена; даты/время/числа/размеры — только `fmt.*` из `lib/format.ts` (`Intl.*` текущей локали), без `'ru-RU'` в коде. Мемо-компоненты подписываются `useLocale()`.
- **Английский**: sentence case («Create room»), коротко, в духе Slack/Discord; кнопки — не длиннее русского более чем на 60 % (unit-тест предупреждает), иначе сокращаем.
- **Проверки**: `i18n.keys.test.ts` — у каждой локали ровно ключи `ru`, те же плейсхолдеры и все плюральные категории языка (падает); длина кнопок — предупреждение. Визуальные эталоны — на `ru` (тесты фиксируют `--lang=ru` / `locale: 'ru-RU'`); для `en` — по снимку главных экранов (`-g "i18n-en"`, dark 960).

## Мобильный веб (ADR-0021, iOS Safari)

- **Один экран, не страница**: оболочка ровно `100dvh` (фолбэк `-webkit-fill-available`, не `100vh` — на iOS это высота со скрытыми тулбарами), `html/body` без скролла и `overscroll`; скроллится только лента/списки внутри. При клавиатуре (поле в фокусе и `visualViewport` ниже layout-вьюпорта) высота = `visualViewport.height`, композер прилипает к клавиатуре, шторки и sheet-диалоги поднимаются на `--kb-inset`; документ, прокрученный iOS к полю, всегда возвращается к верху (`lib/mobile.ts`).
- **С экрана «Домой» (standalone PWA)**: панелей Safari нет — никакой компенсации тулбара, оболочка `100dvh`, снизу только `env(safe-area-inset-bottom)` у последнего элемента (композер/полоса звонка), не у всей оболочки. `<html>` получает `pwa-standalone` (`display-mode: standalone` или `navigator.standalone`).
- Если iOS в standalone отдаёт вьюпорт короче экрана (баг WebKit с `black-translucent`: минус статус-бар/индикатор Home, ≤ 100 px, окно на всю ширину) — `--app-height` = высота экрана (`screen`), иначе под композером остаётся пустая полоса (`lib/mobile.ts`).
- Тесты: `m-chat-standalone` (снимок) и `mobile.web.spec` «home-screen app» — эмуляция standalone, зазор под композером ≤ safe-area-inset-bottom, укороченный вьюпорт растягивается до экрана.
- **Фокус только по тапу**: на телефоне ни экран, ни диалог, ни смена комнаты, ни конец онбординга не фокусируют поле программно (iOS прокручивает/зумит к нему и поднимает клавиатуру) — `autoFocusAllowed()` из `lib/phone.ts`. Исключение — явное действие «Ответить»/«Изменить».
- **Safe areas**: `viewport-fit=cover`, отступы через `--safe-*` (= `env(safe-area-inset-*)`) — верх у оболочки и полноэкранных страниц (вход, онбординг, join), низ у последнего элемента (полоса звонка или композер), у шторок и sheet'ов.
- **Касания**: цели в шапке и полосе звонка ≥ 40×40 и не пересекаются на 375 px; поля 16 px (иначе iOS зумит); `touch-action: manipulation` на контролах (у PTT — `none`), без tap-highlight. Тосты — сверху под шапкой и под шторками/sheet'ами (внизу они закрывают композер и полосу).
- **Тесты**: `e2e-visual/mobile.visual.spec.ts` — WebKit (iPhone 14 / SE / 14 Pro Max), снимки 390 px dark, инварианты (нет гориз. скролла и прокрутки документа, ничего за экраном, композер виден, нет пустой полосы > 24 px под последним элементом, цели 40 px), axe; клавиатура — подменой `visualViewport`.

## Почта (ADR-0023)

- **Плашка «Подтвердите почту»** — тонкая полоса (`bg-mention`) над основным контентом, десктоп и телефон, пока `me.emailVerified = false`; не закрывается — уходит только после кода (тост «Почта подтверждена»). Текст «Мы отправили код на …» (`pendingEmail`, иначе `email`), поле 6 цифр (`inputMode=numeric`, `one-time-code`, 6 цифр отправляются сами), «Подтвердить», «Отправить снова» — таймер 60 с после отправки или из `Retry-After` 429. Ошибки inline: `CODE_INVALID` с числом оставшихся попыток, `CODE_EXPIRED` — «Отправьте новый».
- **Заблокированное действие** (403 `EMAIL_NOT_VERIFIED`: создать пространство, пригласить, новый DM) закрывает диалог, плашка получает фокус (на телефоне — только подсветку, поле по тапу) и меняет текст на «зачем».
- **Онбординг**: для неподтверждённого аккаунта шаг «Подтвердите почту» — первым («Позже» оставляет плашку). Регистрация шлёт `locale` текущего языка; `me.locale` следует за сменой языка.
- **Вход**: «Забыли пароль?» справа на строке подписи пароля → email → «Если … зарегистрирован, мы отправили код» → код + новый пароль → вход с ним. Регистрация по ссылке из письма: email заполнен и заблокирован (превью `/api/invites/{code}` публичное).
- **Смена email** (Профиль): код на новый адрес вторым шагом того же листа; в строке email — «… — ожидает подтверждения · Ввести код · Отменить» (отмена — паролем).
- **Пригласить по email** (Настройки пространства → Приглашения, первым): точный адрес → поиск через 400 мс только для валидного email → карточка (аватар, имя, «Добавить» или «Уже участник») либо «Отправить приглашение на почту» (+ роль для владельца); ниже «Отправленные приглашения» с «Отозвать». Ссылки/коды — без изменений.
- Снимки (dark 960): `verify-banner`, `invite-email`, `auth-forgot`.

  - **Nightly CI на Linux (`CALABA_VISUAL_ALL=1`, эталоны `linux/`)** — полная матрица: все экраны (все вкладки настроек, варианты меню, тосты…), light и dark, 960 и 1440, обход фокуса, экраны веб-клиента. Остальные тесты в спеке локально помечены `skip`, код не удаляется.
